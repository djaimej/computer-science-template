# Inteligencia Artificial - Búsqueda

## 2.4 Problemas de satisfacción con restricciones.

---

Muchos problemas no piden un camino sino una **asignación**: dar a cada variable un valor de modo que se cumplan ciertas restricciones. Programar exámenes sin choques, colorear un mapa, resolver un Sudoku, asignar frecuencias a antenas o configurar un producto son ejemplos. Un **problema de satisfacción de restricciones** (CSP) los representa con una estructura común, y esa estructura permite técnicas mucho más eficientes que la búsqueda genérica: propagar las restricciones para reducir los dominios antes y durante la búsqueda, y elegir con heurísticas qué variable y qué valor probar. Este tema presenta la formulación, el backtracking, la propagación con verificación hacia adelante y consistencia de arcos, y las heurísticas de ordenamiento.

### Formulación

Un CSP es una terna $(X, D, C):$ un conjunto de **variables** $X = \{X_1, \dots, X_n\},$ un **dominio** $D_i$ de valores posibles para cada una, y un conjunto de **restricciones** $C,$ cada una sobre un subconjunto de variables, que especifica las combinaciones de valores permitidas. Una **solución** es una asignación completa y consistente. Las restricciones binarias, entre dos variables, se representan con un **grafo de restricciones**; las de más variables, como "todas distintas", pueden reducirse a binarias o tratarse con algoritmos propios. Resolver un CSP con dominios finitos es NP-completo en general, porque incluye a SAT.

### Backtracking

La búsqueda con **retroceso** asigna una variable a la vez, comprueba que la asignación parcial sea consistente, y si no hay valor válido para la variable actual, retrocede. Es una búsqueda en profundidad que aprovecha que el orden de asignación no importa. Su eficiencia depende de tres decisiones.

### Heurísticas de ordenamiento

- **Qué variable:** la de **mínimos valores restantes** (MRV), la más restringida, porque si va a fallar, falla pronto. Para desempatar, la heurística de **grado**: la que participa en más restricciones con variables sin asignar.
- **Qué valor:** el **menos restrictivo** (LCV), el que elimina menos valores de los dominios de los vecinos, porque deja más opciones para el resto. Es útil cuando se busca una sola solución.

MRV elige la variable que más probablemente falle, y LCV el valor que más probablemente funcione: "falla primero en las variables, acierta primero en los valores".

### Propagación de restricciones

- **Verificación hacia adelante** (*forward checking*): al asignar una variable, elimina de los dominios de sus vecinos los valores inconsistentes; si un dominio queda vacío, retrocede de inmediato, sin esperar a llegar a esa variable.
- **Consistencia de arcos:** un arco $X \to Y$ es consistente si para cada valor de $X$ hay algún valor compatible de $Y.$ El algoritmo **AC-3** (Mackworth, 1977) mantiene una cola de arcos; al revisar $X \to Y$ elimina de $D_X$ los valores sin apoyo, y si elimina alguno, vuelve a encolar los arcos $Z \to X.$ Su complejidad es $O(e\,d^3),$ con $e$ las restricciones y $d$ el tamaño de los dominios. Puede usarse como preprocesamiento o en cada paso de la búsqueda, el método MAC.

La consistencia de arcos no siempre basta para resolver un problema, pero reduce mucho la búsqueda; para problemas con estructura de árbol, garantiza una solución sin retroceso en tiempo lineal.

```mermaid

    S --> V["Elegir valor: LCV"]
```

### Implementación en Python

El programa implementa un resolvedor de CSP binarios con backtracking, verificación hacia adelante y las heurísticas MRV, grado y LCV, y lo aplica a los cuatro ejercicios: compara las combinaciones de técnicas en las N reinas para N = 8, 12 y 16; resuelve el horario; aplica AC-3 al problema del ejercicio 3 mostrando cada eliminación, y resuelve el Sudoku.

```python
from collections import deque
from itertools import product

# ---------- Un resolvedor de CSP binarios con backtracking, heurísticas y verificación hacia adelante ----------
class CSP:
    def __init__(self, variables, dominios, restricciones):
        self.V, self.D = variables, {v: list(dominios[v]) for v in variables}
        self.R = restricciones                                  # {(x, y): función(a, b) → bool}, en ambos sentidos
        self.vecinos = {v: [y for (x, y) in self.R if x == v] for v in variables}
    def consistente(self, x, a, asig):
        return all(self.R[(x, y)](a, asig[y]) for y in self.vecinos[x] if y in asig)
    def resuelve(self, mrv=False, grado=False, lcv=False, fc=False):
        self.asignaciones = 0
        return self._bt({}, {v: list(d) for v, d in self.D.items()}, mrv, grado, lcv, fc)
    def _bt(self, asig, dom, mrv, grado, lcv, fc):
        if len(asig) == len(self.V): return dict(asig)
        libres = [v for v in self.V if v not in asig]
        if mrv: libres.sort(key=lambda v: (len(dom[v]), -sum(1 for y in self.vecinos[v] if y not in asig) if grado else 0))
        elif grado: libres.sort(key=lambda v: -sum(1 for y in self.vecinos[v] if y not in asig))
        x = libres[0]
        valores = dom[x]
        if lcv:
            valores = sorted(valores, key=lambda a: sum(1 for y in self.vecinos[x] if y not in asig for b in dom[y] if not self.R[(x, y)](a, b)))
        for a in valores:
            if not self.consistente(x, a, asig): continue
            self.asignaciones += 1; asig[x] = a
            nuevo = dom
            if fc:                                              # verificación hacia adelante: poda los dominios de los vecinos
                nuevo = {v: list(d) for v, d in dom.items()}; nuevo[x] = [a]
                for y in self.vecinos[x]:
                    if y not in asig: nuevo[y] = [b for b in nuevo[y] if self.R[(x, y)](a, b)]
                if any(not nuevo[y] for y in self.vecinos[x] if y not in asig): del asig[x]; continue
            r = self._bt(asig, nuevo, mrv, grado, lcv, fc)
            if r: return r
            del asig[x]
        return None

# ---------- Ejercicio 1: N reinas ----------
def reinas(n):
    V = list(range(n)); R = {}
    for i in V:
        for j in V:
            if i != j: R[(i, j)] = (lambda i, j: lambda a, b: a != b and abs(a - b) != abs(i - j))(i, j)
    return CSP(V, {v: range(n) for v in V}, R)
print("ejercicio 1: asignaciones hasta la primera solución de N reinas")
for n in (8, 12, 16):
    fila = []
    for nombre, kw in (("backtracking", {}), ("FC", {"fc": True}), ("FC+MRV+grado", {"fc": True, "mrv": True, "grado": True}),
                       ("FC+MRV+grado+LCV", {"fc": True, "mrv": True, "grado": True, "lcv": True})):
        c = reinas(n); s = c.resuelve(**kw); fila.append(f"{nombre} {c.asignaciones}")
        assert all(c.R[(i, j)](s[i], s[j]) for (i, j) in c.R)
    print(f"   N = {n:2}: " + " | ".join(fila))

# ---------- Ejercicio 2: horario ----------
cursos = ["Matemáticas", "Física", "Química", "Historia"]
valores = list(product(["A1", "A2", "A3"], ["9:00", "11:00", "14:00"]))
dom = {c: [(a, h) for a, h in valores if not (a == "A1" and h == "14:00")] for c in cursos}       # A1 solo en la mañana
dom["Química"] = [(a, h) for a, h in dom["Química"] if h == "14:00"]                               # después de las 12:00
R = {}

h = CSP(cursos, dom, R); sol = h.resuelve(fc=True, mrv=True)

# ---------- Ejercicio 3: AC-3 ----------
def ac3(D, R, traza):
    D = {v: set(d) for v, d in D.items()}; cola = deque(R)
    while cola:
        x, y = cola.popleft()
        quitar = {a for a in D[x] if not any(R[(x, y)](a, b) for b in D[y])}
        if quitar:
            D[x] -= quitar; traza.append(f"arco {x}→{y}: elimina {sorted(quitar)} de {x}")
            cola.extend((z, x) for (z, w) in R if w == x and z != y)
    return D
R3 = {("A", "B"): lambda a, b: a != b, ("B", "A"): lambda a, b: a != b, ("B", "C"): lambda a, b: a != b, ("C", "B"): lambda a, b: a != b,
      ("A", "C"): lambda a, c: a > c, ("C", "A"): lambda c, a: a > c}
traza = []; D3 = ac3({v: {1, 2, 3} for v in "ABC"}, R3, traza)
print("ejercicio 3:", traza, "→ dominios", {v: sorted(d) for v, d in D3.items()})
c3 = CSP(list("ABC"), {v: sorted(d) for v, d in D3.items()}, R3); s3 = c3.resuelve()
todas = [s for s in product([1, 2, 3], repeat=3) if s[0] != s[1] and s[1] != s[2] and s[0] > s[2]]
print("   soluciones (A, B, C):", todas)

# ---------- Ejercicio 4: Sudoku con verificación hacia adelante ----------
S = ("530070000600195000098000060800060003400803001700020006060000280000419005000080079")

Rs = {(p, q): (lambda a, b: a != b) for p in celdas for q in celdas if mismos(p, q)}
Ds = {(f, c): [int(S[f * 9 + c])] if S[f * 9 + c] != "0" else list(range(1, 10)) for f, c in celdas}
```

### Ejercicios Propuestos

### Soluciones

**Ejercicio 1.** Cada variable es una columna y su valor la fila de su reina; las restricciones prohíben la misma fila y la misma diagonal. Las asignaciones necesarias hasta la primera solución:

| N  | Backtracking | FC    | FC + MRV + grado | FC + MRV + grado + LCV |
| -- | ------------ | ----- | ---------------- | ---------------------- |
| 8  | 113          | 88    | 75               | 39                     |
| 12 | 261          | 193   | 153              | 32                     |
| 16 | 10 052       | 7 560 | 44               | 332                    |

La verificación hacia adelante reduce las asignaciones en todos los casos, y MRV produce el salto mayor para N = 16, de 7 560 a 44. LCV ayuda en 8 y 12 pero empeora en 16: las heurísticas reducen la búsqueda **en promedio**, no en cada instancia, y el número exacto depende del orden de los desempates. Para N grande, las N reinas se resuelven mejor con búsqueda local, como el algoritmo de conflictos mínimos, que resuelve un millón de reinas en pocos pasos.

**Ejercicio 2.** Cada curso es una variable cuyo valor es un par (aula, horario), 9 valores. Las restricciones unarias reducen los dominios: A1 pierde las 14:00 y Química solo conserva las 14:00 en A2 o A3. Las binarias son que dos cursos no ocupen el mismo par, y que Matemáticas y Física no compartan horario. Con verificación hacia adelante y MRV, el resolvedor empieza por Química, la más restringida, y encuentra **Química en A2 a las 14:00, Matemáticas en A1 a las 9:00, Física en A1 a las 11:00 e Historia en A2 a las 9:00**. Hay muchas otras soluciones; para elegir una, se agrega una función de costo, como minimizar los cambios de aula de los profesores, y el problema se vuelve de optimización con restricciones.

**Ejercicio 3.** AC-3 revisa cada arco:

1. $A \to C$ con $A \gt C:$ $A = 1$ no tiene apoyo, porque ningún $C$ es menor que 1; se elimina, $D_A = \{2, 3\}.$
2. $C \to A:$ $C = 3$ no tiene apoyo, porque ningún $A$ es mayor que 3; se elimina, $D_C = \{1, 2\}.$
3. Los arcos de $\ne$ no eliminan nada: con dominios de al menos dos valores, siempre hay un valor distinto que sirve de apoyo.

Los dominios finales son $D_A = \{2, 3\},$ $D_B = \{1, 2, 3\},$ $D_C = \{1, 2\}.$ AC-3 no resolvió el problema, pero redujo el espacio de 27 combinaciones a 12, y las soluciones son tres: $(A, B, C) = (2, 3, 1),$ $(3, 1, 2)$ y $(3, 2, 1).$ La consistencia de arcos no detecta que $B$ tampoco puede tomar cualquier valor en cada combinación: eso requiere consistencia de caminos o búsqueda.

**Ejercicio 4.** Cada celda es una variable, con dominio $\{1, \dots, 9\}$ o el valor dado, y las restricciones son de desigualdad entre las celdas de la misma fila, columna o caja. Con verificación hacia adelante en orden de lectura, la búsqueda hace 11 400 asignaciones; agregando MRV, solo 81, una por celda, sin un solo retroceso: el Sudoku se resuelve por pura propagación con la variable más restringida. Sin propagación, el backtracking simple necesitó más de 14 millones de asignaciones en una prueba aparte, y por eso el programa no lo incluye. La solución es la del programa.

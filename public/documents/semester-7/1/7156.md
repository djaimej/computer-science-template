# Compiladores - Representaciones intermedias

## 5.6 Tablas de símbolos.

---

La **tabla de símbolos** es la estructura que acompaña a todas las representaciones intermedias: guarda lo que el compilador sabe de cada nombre del programa, su clase, su tipo, su ámbito, su almacenamiento y su dirección, para que cualquier fase lo consulte en tiempo constante. La construye el análisis semántico, la usan el generador de código intermedio y el *back-end*, y parte de ella termina en el archivo objeto como la tabla de símbolos del enlazador y la información de depuración. Este tema presenta qué se guarda, cómo se implementan las tablas y los ámbitos, cómo se representan los tipos compuestos con su disposición en memoria, y cómo hacer eficientes las operaciones, comparando cada respuesta con lo que hace gcc.

### Qué se guarda

| Atributo | Para qué sirve |
| -------- | -------------- |
| nombre | la clave de búsqueda; en C++ también el nombre **decorado** que ve el enlazador |
| clase | variable, constante, parámetro, función, tipo, campo, etiqueta |
| tipo | una expresión de tipo, con sus constructores: arreglos, registros, apuntadores, funciones |
| ámbito | dónde es visible el nombre |
| almacenamiento | estático, en la pila, en el montículo o en un registro; define la duración |
| dirección | desplazamiento en el registro de activación o etiqueta en el segmento de datos |
| tamaño y alineación | para calcular las direcciones de los campos y de los elementos |
| otros | valor de las constantes, número y tipos de los parámetros, si se toma la dirección, línea de la declaración |

El **ámbito** y la **duración** son independientes: una variable `static` local tiene ámbito de función pero duración de todo el programa.

### Implementación

La tabla debe insertar y buscar muy rápido, porque cada uso de un nombre implica una búsqueda. Las opciones son:

- **tabla de dispersión:** inserción y búsqueda en $O(1)$ **esperado**, con una buena función de dispersión y factor de carga acotado; en el peor caso, $O(n).$ Es la opción de casi todos los compiladores;
- **árbol de búsqueda balanceado:** $O(\log n)$ garantizado y recorrido en orden, útil para listados;
- **lista:** $O(n)$ por búsqueda; solo sirve para tablas pequeñas.

Para los **ámbitos anidados** hay dos esquemas:

1. **pila de tablas:** una tabla por ámbito; buscar recorre la pila del tope a la base, en $O(d)$ sondeos con $d$ niveles, y cerrar un ámbito es desapilar su tabla;
2. **tabla única con pilas por nombre:** una sola tabla de dispersión en la que cada nombre tiene la pila de sus declaraciones visibles, más una lista por ámbito de los nombres que declaró; buscar es un sondeo, y cerrar un ámbito desapila esas declaraciones, en tiempo proporcional a lo que declaró. Es el esquema clásico de los compiladores de un solo pase.

Insertar debe detectar la **redeclaración** en el mismo ámbito y puede advertir el **ocultamiento** de una declaración exterior.

```mermaid
flowchart LR
    P["Análisis semántico"] -->|"insertar"| T["Tabla de símbolos"]
    P -->|"buscar"| T
    T --> G["Generación de código: direcciones y tamaños"]
    T --> O["Optimización: alias y constantes"]
    T --> E["Archivo objeto: símbolos para el enlazador y DWARF"]
```

### Tipos compuestos y disposición en memoria

Un registro guarda la lista de sus campos con su tipo y su **desplazamiento**, calculado con las reglas de **alineación** de la plataforma: cada campo empieza en un múltiplo de su alineación, y el tamaño total se redondea al múltiplo de la mayor alineación de sus campos, para que los elementos de un arreglo de registros también queden alineados. En x86-64, `int` y `float` ocupan 4 bytes y se alinean a 4, y `char` a 1. Un arreglo guarda su tipo de elemento y sus dimensiones; su tamaño es el producto, y la dirección de `a[i]` es $\text{base} + i \cdot \text{tamaño del elemento}.$ Un `typedef` agrega un nombre de la clase **tipo** que apunta a la misma expresión de tipo.

class PilaDeTablas:
    def __init__(self): self.pila = [{}]; self.sondeos = 0
    def entra(self): self.pila.append({})
    def sale(self): self.pila.pop()
    def inserta(self, n, info):
        if n in self.pila[-1]: return f"error: '{n}' ya declarado en este ámbito"
        aviso = f"aviso: '{n}' oculta una declaración exterior" if any(n in t for t in self.pila[:-1]) else None
        self.pila[-1][n] = info; return aviso
    def busca(self, n):
        for nivel in range(len(self.pila) - 1, -1, -1):
            self.sondeos += 1
            if n in self.pila[nivel]: return nivel, self.pila[nivel][n]
        return None
class TablaUnica:
    """Una sola tabla de dispersión; cada nombre tiene una pila de declaraciones, y cada ámbito la lista de lo que declaró."""
    def __init__(self): self.tabla, self.ambitos, self.sondeos = {}, [[]], 0
    def entra(self): self.ambitos.append([])
    def sale(self):
        for n in self.ambitos.pop():
            self.tabla[n].pop()
            if not self.tabla[n]: del self.tabla[n]
    def inserta(self, n, info):
        pila = self.tabla.setdefault(n, [])
        if pila and pila[-1][0] == len(self.ambitos) - 1: return f"error: '{n}' ya declarado en este ámbito"
        aviso = f"aviso: '{n}' oculta una declaración exterior" if pila else None
        pila.append((len(self.ambitos) - 1, info)); self.ambitos[-1].append(n); return aviso
    def busca(self, n):
        self.sondeos += 1
        return self.tabla[n][-1] if n in self.tabla else None
for T in (PilaDeTablas, TablaUnica):

# ---------- Ejercicio 4: tipos compuestos, desplazamientos y alineación ----------
TAM = {"int": (4, 4), "char": (1, 1), "float": (4, 4)}
def disposicion(campos):
    desp, alin_max, res = 0, 1, []
    for nombre, tipo, n in campos:
        tam, alin = TAM[tipo]
        desp = (desp + alin - 1) // alin * alin; res.append((nombre, desp, tam * n)); desp += tam * n; alin_max = max(alin_max, alin)
    total = (desp + alin_max - 1) // alin_max * alin_max
    return res, total, alin_max
campos, total, alin = disposicion([("id", "int", 1), ("name", "char", 50), ("scores", "float", 10)])
print("ejercicio 4: Student:", campos, f"tamaño {total}, alineación {alin}; classroom: {30 * total} bytes")

# ---------- Ejercicio 5: costo de las búsquedas, caché y su invalidación ----------
for T in (PilaDeTablas, TablaUnica):
    t = T(); t.inserta("g", "global")
    for _ in range(50): t.entra()
    for _ in range(1000): t.busca("g")
    print(f"ejercicio 5: {T.__name__:13} 1000 búsquedas de un global con 50 ámbitos abiertos: {t.sondeos} sondeos")
class ConCache(PilaDeTablas):
    def __init__(self, invalida): super().__init__(); self.cache, self.invalida = {}, invalida
    def inserta(self, n, info):
        if self.invalida: self.cache.pop(n, None)
        return super().inserta(n, info)
    def sale(self):
        if self.invalida: self.cache.clear()
        super().sale()
    def busca(self, n):
        if n not in self.cache: self.cache[n] = super().busca(n)
        return self.cache[n]
for invalida in (False, True):
    t = ConCache(invalida); t.inserta("x", "global"); t.entra(); antes = t.busca("x"); t.inserta("x", "local"); despues = t.busca("x")
    print(f"   caché {'con' if invalida else 'sin'} invalidación: antes {antes}, después de declarar una x local {despues}")

### Ejercicios Propuestos

1. **Diseño.** Diseña la estructura de la tabla de símbolos para el código:

    ```c
    const int MAX = 100;
    float data[MAX];
    void process(int count) {
        static int calls = 0;
        float temp[count];
        calls++;
    }
    ```

2. **Ámbitos anidados.** Implementa una tabla de símbolos con ámbitos anidados que permita insertar y buscar en el ámbito actual, buscar en los ámbitos exteriores y manejar el ocultamiento de variables.

3. **Resolución.** Traza la búsqueda de los símbolos en el código:

    ```c
    int x = 1;
    void outer() {
        int x = 2;
        {
            int x = 3;
            printf("%d", x);
        }
    }
    ```

4. **Tipos compuestos.** Diseña las entradas para:

    ```c
    typedef struct {
        int id;
        char name[50];
        float scores[10];
    } Student;
    Student classroom[30];
    ```

5. **Optimización.** Propón optimizaciones para la búsqueda en ámbitos profundamente anidados, la inserción masiva de símbolos y la verificación de tipos en expresiones complejas.

### Soluciones

**Ejercicio 1.** Primero, el código **no es C válido**: en C, una variable `const int` no es una expresión constante entera, así que `float data[MAX]` en el ámbito global sería un arreglo de tamaño variable, que solo se permite en ámbitos de bloque; gcc lo rechaza con "variably modified 'data' at file scope". En C++ sí es válido, y en C se escribe `#define MAX 100` o `enum { MAX = 100 }`. Con esa corrección, las entradas son las de la tabla del programa: `MAX` como constante, que con `#define` ni siquiera llega a la tabla de símbolos; `data` como arreglo global de 100 `float`, 400 bytes en `.bss`, porque no tiene inicializador; `process` como función $\text{int} \to \text{void};$ `count` como parámetro; `calls` con ámbito de `process` pero **almacenamiento estático**, y `temp` como arreglo de tamaño variable, que se reserva en la pila al ejecutar. `nm` confirma la distinción entre ámbito y duración: `data` aparece como símbolo global en `.bss`, `B`; `process` en `.text`, `T`; una constante global con valor, como `LIMITE`, en `.rodata`, `R`, y `calls` como símbolo **local** del objeto, `b`, con un nombre cambiado, `calls.0`, para que no choque con otra `calls` estática de otra función. `count` y `temp` no aparecen, porque viven en la pila.

**Ejercicio 2.** Las dos implementaciones del programa, la pila de tablas y la tabla única con pilas por nombre, dan las mismas respuestas: al declarar `x` dentro del bloque advierten que oculta a la global; al declararla otra vez en el mismo bloque reportan el error; dentro del bloque, `x` es la local y `y` la global, y al salir, `x` vuelve a ser la global.

**Ejercicio 3.** Al llegar al `printf` interior hay tres ámbitos abiertos, el global con `x = 1`, el de `outer` con `x = 2` y el del bloque con `x = 3`. La búsqueda empieza en el ámbito del bloque, encuentra `x` y **se detiene**: no consulta los otros dos. El programa imprime 3. Si se agrega un `printf` después del bloque, el ámbito interior ya se cerró y se imprime 2, y desde `main`, 1, como confirma la ejecución real.

**Ejercicio 4.** Hay tres entradas. El tipo, `Student`, de clase **tipo**, con una expresión de registro sin etiqueta y sus campos: `id`, `int`, desplazamiento 0; `name`, arreglo de 50 `char`, desplazamiento 4, y `scores`, arreglo de 10 `float`, desplazamiento **56**, no 54, porque un `float` se alinea a 4 y se agregan 2 bytes de relleno. El tamaño es 96 bytes, con alineación 4. La variable `classroom` es un arreglo de 30 `Student`, de 2 880 bytes, y la dirección de `classroom[i].scores[j]` es $\text{base} + 96 i + 56 + 4 j.$ gcc da exactamente esos desplazamientos y tamaños.

**Ejercicio 5.** Para la **búsqueda profunda**, la tabla única con pilas por nombre hace un solo sondeo por búsqueda, contra uno por nivel de la pila de tablas: con 50 ámbitos abiertos, 1 000 búsquedas de un global cuestan 1 000 sondeos en lugar de 51 000. Una **caché** de búsquedas también ayuda, pero debe **invalidarse** al declarar un nombre que la caché contiene y al cerrar un ámbito: sin invalidación, después de declarar una `x` local, la caché sigue devolviendo la global, un error de resolución. Para la **inserción masiva**, conviene reservar la tabla con el tamaño esperado, para evitar redimensionarla varias veces, e **internar** las cadenas de los nombres al analizarlas, de modo que la tabla compare apuntadores y no cadenas. Para la **verificación de tipos**, conviene representar los tipos de forma **canónica**, construyendo cada expresión de tipo una sola vez con numeración de valores, de modo que la equivalencia estructural sea una comparación de apuntadores, y guardar en cada nodo del árbol el tipo ya calculado para no recalcularlo.

En el material original, el ejemplo de tipos compuestos declaraba `Point centers[10];`, que en C requiere `struct Point` o un `typedef`; la caché de búsquedas nunca se invalidaba, con el error que muestra el programa; la tabla de complejidad daba $O(1)$ a la tabla de dispersión sin aclarar que es el caso esperado y $O(\log n)$ al árbol sin aclarar que debe estar balanceado, y el texto usaba palabras en inglés como "scope nesting" y "codebases".

# Ingeniería de Software - Evolución de los sistemas de software

## 7.6 Refactoring.

---

**Refactorizar** es cambiar la estructura interna de un software para hacerlo más fácil de entender y de modificar, **sin cambiar su comportamiento observable**. Fowler lo definió así en su libro de 1999, que catalogó las refactorizaciones como transformaciones con nombre, con una motivación y una mecánica paso a paso, a partir del trabajo de Opdyke en su tesis de 1992. Refactorizar es la forma cotidiana de pagar la deuda técnica (tema 7.1) y de contrarrestar la ley de Lehman de la complejidad creciente. Este tema presenta cuándo refactorizar, los olores del código que lo indican, las refactorizaciones más comunes, la red de seguridad que requieren y cómo planear la refactorización de un sistema grande.

### Cuándo refactorizar

Refactorizar no es una fase del proyecto, sino una actividad continua: antes de agregar una función, para que sea fácil agregarla; al corregir un defecto, para que el código sea más claro; durante la revisión de código, y en el paso de refactorización de cada ciclo de TDD (tema 6.7). Fowler resume la regla de Beck: primero haz que el cambio sea fácil, y después haz el cambio fácil. La **regla del campamento** pide dejar el código un poco mejor de como se encontró.

No se refactoriza un código que se va a reescribir, ni sin pruebas, ni mezclado con cambios de comportamiento en el mismo commit.

### Olores del código

Los **olores** (*code smells*) son síntomas de un problema de diseño:

- **método largo** y **clase grande**;
- **código duplicado**;
- **lista larga de parámetros**;
- **condicionales repetidos** sobre un tipo, que piden polimorfismo;
- **envidia de funcionalidad**: un método que usa más los datos de otra clase que los de la suya;
- **obsesión por los primitivos**: usar cadenas o números donde debería haber un tipo, como el dinero;
- **cirugía de escopeta**: un cambio que obliga a tocar muchas clases;
- **comentarios** que explican código confuso en lugar de aclararlo.

### Refactorizaciones comunes

- **Extraer método:** un fragmento con un propósito se convierte en un método con un nombre que lo describe. Es la más usada.
- **Extraer clase**, **mover método** y **mover campo:** repartir responsabilidades.
- **Renombrar:** un buen nombre es la refactorización más barata y una de las más valiosas.
- **Introducir objeto de parámetro** y **preservar el objeto completo**.
- **Reemplazar el condicional por polimorfismo:** cada rama de un `switch` sobre un tipo se convierte en una subclase o en una estrategia.
- **Reemplazar el número mágico por una constante** y **reemplazar el primitivo por un objeto.**
- **Separar consulta y modificación:** un método que devuelve un valor no debe además cambiar el estado.

Los entornos de desarrollo modernos aplican muchas de ellas automáticamente y de forma segura.

### Red de seguridad

Como el comportamiento no debe cambiar, cada paso de una refactorización se verifica con las pruebas. Los pasos son pequeños, de modo que si una prueba falla se sabe cuál fue la causa y se revierte. Sin pruebas, primero se escriben las de caracterización. Para un sistema grande, la refactorización se **prioriza** cruzando la complejidad con la frecuencia de cambios: los **puntos calientes** que cambian a menudo y son complejos dan el mayor retorno (tema 1.5), y el código complejo que nunca cambia puede quedarse como está.

class Canal(ABC):
    registro = {}
    def __init_subclass__(cls, tipo=None, **kw):              # cada subclase se registra sola
        super().__init_subclass__(**kw)
        if tipo: Canal.registro[tipo] = cls
    @abstractmethod
    def envia(self, destino: str, mensaje: str) -> str: ...
class Email(Canal, tipo="EMAIL"):
    def envia(self, destino, mensaje): return f"correo a {destino}: {mensaje}"

### Soluciones

**Ejercicio 1.** El método mezcla tres cosas: calcular el resumen, formatear y escribir en la consola. La refactorización extrae el **cálculo** a un método puro, `summarize`, que devuelve un objeto con los totales, y la **presentación** a tres métodos, para el encabezado, cada línea y el pie. Dos cambios más, que la extracción hace evidentes: la fecha se recibe como parámetro en lugar de leer `LocalDate.now()`, y el reporte se devuelve como texto en lugar de imprimirse, de modo que el método es comprobable. Además, el original usaba `double` para el dinero, y con ventas de 1200.10, 0.20 y 0.10 habría impreso un total de 1200.3999999999999; la versión refactorizada usa `BigDecimal`. Este cambio sí altera la salida, y por eso es una corrección, que conviene hacer en un commit separado de la refactorización:

```java
import java.math.BigDecimal;
import java.time.LocalDate;
import java.util.*;

record Sale(String productName, String category, BigDecimal amount, int quantity) {}
record SalesSummary(BigDecimal totalRevenue, int totalUnits, Map<String, Integer> countByCategory) {}

class SalesReport {
    public String generateReport(List<Sale> sales, LocalDate date) {
        StringBuilder out = new StringBuilder();
        appendHeader(out, date);
        sales.forEach(sale -> appendLine(out, sale));
        appendFooter(out, summarize(sales));
        return out.toString();
    }
    static SalesSummary summarize(List<Sale> sales) {
        BigDecimal revenue = BigDecimal.ZERO;
        int units = 0;
        Map<String, Integer> byCategory = new TreeMap<>();
        for (Sale s : sales) {
            revenue = revenue.add(s.amount());
            units += s.quantity();
            byCategory.merge(s.category(), 1, Integer::sum);
        }
        return new SalesSummary(revenue, units, byCategory);
    }
    private void appendHeader(StringBuilder out, LocalDate date) {
        out.append("=== SALES REPORT ===\nDate: ").append(date).append("\n-------------------\n");
    }
    private void appendLine(StringBuilder out, Sale s) {
        out.append(s.productName()).append(": $").append(s.amount()).append(" (").append(s.quantity()).append(" units)\n");
    }
    private void appendFooter(StringBuilder out, SalesSummary sum) {
        out.append("-------------------\nTotal Revenue: $").append(sum.totalRevenue())
           .append("\nTotal Units: ").append(sum.totalUnits())
           .append("\nBy Category: ").append(sum.countByCategory()).append("\n");
    }
}
```

Con esas tres ventas, el resultado es el reporte con `Total Revenue: $1200.40`, `Total Units: 6` y `By Category: {computo=2, libros=1}`. El `TreeMap` hace que el orden de las categorías sea determinista.

**Ejercicio 2.** Cada rama se convierte en una subclase de `Canal` con su método `envia`, y una función `canal(tipo)` busca la subclase en un registro. En el programa, las subclases se registran solas al definirse, con `__init_subclass__`, de modo que agregar WhatsApp es escribir una clase nueva, sin tocar ninguna línea existente; con el condicional había que modificar el método `send` cada vez. El error para un tipo desconocido se conserva. Si los canales no tienen estado, una alternativa más ligera en Python es un diccionario de funciones.

**Ejercicio 3.** $V(G) = 20 - 15 + 2 = 7,$ y

$$\mathrm{MI} = 171 - 5.2 \ln 450 - 0.23 \cdot 7 - 16.2 \ln 80 \approx 171 - 31.8 - 1.6 - 71.0 \approx 66.6,$$

39 en la escala normalizada: mantenible según el umbral de 20, aunque mejorable. La función de 80 líneas es candidata a extraer métodos; con cuatro funciones de 20 líneas, el índice de cada una subiría a más de 90.

**Ejercicio 4.** En el cuadrante de Fowler:

- **Tecnología nueva para ganar experiencia:** deliberada y prudente, si el equipo acepta el riesgo de forma consciente y tiene un plan para cambiar si no madura.
- **Código sin pruebas para una fecha:** deliberada; prudente solo si se registra como deuda y se paga en cuanto pasa la fecha, e imprudente si se repite como costumbre.
- **Crecimiento orgánico sin diseño:** inadvertida e imprudente, la más cara, porque nadie la registró y se acumula sin control.
- **Vulnerabilidad descubierta en una biblioteca:** inadvertida y prudente, porque no se sabía; para algunos autores no es deuda técnica sino un riesgo externo. Se vuelve imprudente si, conocida, no se actualiza la biblioteca.

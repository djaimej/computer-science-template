# Autómatas y Lenguajes Formales - Máquinas de Turing

## 5.4 La máquina de Turing como un procedimiento.

---

Hasta ahora las máquinas de Turing se usaron para **reconocer** lenguajes. Pero Turing las concibió para **calcular**: una máquina recibe datos en la cinta y, al detenerse, deja en ella un resultado. Este tema presenta la máquina de Turing como un procedimiento que calcula funciones, cómo se componen esos procedimientos, y la distinción entre los que siempre terminan, que corresponden a los **algoritmos**, y los que pueden no terminar.

### Máquinas que calculan funciones

Una MT $M$ **calcula** la función $f : \Sigma^* \rightarrow \Sigma^*$ si, para toda entrada $w,$ $M$ se detiene con $f(w)$ escrito en la cinta (y nada más que blancos alrededor). Si $M$ no se detiene con algunas entradas, calcula una **función parcial**: $f(w)$ no está definida donde $M$ cicla.

Para calcular funciones numéricas hay que fijar una representación. Las más comunes son:

- **Unaria:** $n$ se escribe como $0^n$ o $1^n.$ Hace los algoritmos sencillos, pero ocupa un espacio exponencial respecto a la binaria.
- **Binaria:** la usual. Los algoritmos son más complicados, pero eficientes.
- **Varios argumentos:** separados por un símbolo, como $0^m10^n$ para el par $(m, n).$

Una función es **Turing-computable** si alguna MT la calcula. Por la tesis de Church-Turing, son exactamente las funciones calculables por un algoritmo.

### Ejemplo: la resta propia

La **resta propia** es $m \mathbin{\dot{-}} n = \max(m - n, 0).$ Con la entrada $0^m10^n,$ una MT la calcula así:

1. Borrar el primer 0 de $m.$
2. Avanzar más allá del 1 y convertir en 1 el primer 0 de $n;$ los ceros de $n$ ya cancelados quedan como unos.
3. Regresar al principio y repetir.
4. Si en el paso 1 ya no hay ceros de $m$ (se encuentra el 1), el resultado es 0: borrar todo.
5. Si en el paso 2 ya no hay ceros de $n,$ el 0 que se borró en esta ronda no tenía pareja: borrar los unos y escribir de vuelta ese 0. Quedan $m - n$ ceros.

| Estado | Lee | Acción | Significado |
| --- | --- | --- | --- |
| $q_0$ | $0$ | escribe blanco, derecha, $q_1$ | quitar un 0 de $m$ |
| $q_0$ | $1$ | escribe blanco, derecha, $q_5$ | $m$ se agotó |
| $q_1$ | $0$ | derecha | cruzar lo que queda de $m$ |
| $q_1$ | $1$ | derecha, $q_2$ | |
| $q_2$ | $1$ | derecha | cruzar lo ya cancelado |
| $q_2$ | $0$ | escribe 1, izquierda, $q_3$ | cancelar un 0 de $n$ |
| $q_2$ | $\sqcup$ | izquierda, $q_4$ | $n$ se agotó |
| $q_3$ | $0$ o $1$ | izquierda | regresar |
| $q_3$ | $\sqcup$ | derecha, $q_0$ | repetir |
| $q_4$ | $1$ | escribe blanco, izquierda | limpiar |
| $q_4$ | $0$ | izquierda | |
| $q_4$ | $\sqcup$ | escribe 0, termina | devolver el 0 sobrante |
| $q_5$ | $0$ o $1$ | escribe blanco, derecha | limpiar |
| $q_5$ | $\sqcup$ | termina | |

### Composición de procedimientos

Si $M_1$ calcula $f$ y $M_2$ calcula $g,$ la máquina que ejecuta $M_1,$ regresa la cabeza al principio del resultado y luego ejecuta $M_2$ calcula $g \circ f.$ Con esta composición y las subrutinas del tema 5.3 se construyen procedimientos complejos a partir de simples. Por ejemplo:

- **Multiplicación** en unario: por cada 0 de $m,$ llamar a una subrutina que copia $0^n$ al final de la cinta.
- **Máximo** de dos números: comparar con la resta propia; si $m \mathbin{\dot{-}} n = 0,$ el resultado es $n,$ y si no, $m.$
- **Pertenencia a un lenguaje** como función: la **función característica** de $L$ vale 1 si $w \in L$ y 0 si no.

### Algoritmos y semialgoritmos

Una MT que se detiene con toda entrada es un **algoritmo**. Un lenguaje es **decidible** (recursivo) si su función característica es calculable por un algoritmo: una máquina que siempre responde sí o no.

Una MT que se detiene y acepta cuando la respuesta es sí, pero que puede ciclar cuando es no, es un **semialgoritmo**. Un lenguaje es **semidecidible** (recursivamente enumerable) si lo reconoce un semialgoritmo.

Un ejemplo de semialgoritmo: dado un polinomio con coeficientes enteros, buscar una raíz entera probando $0, 1, -1, 2, -2, \ldots$ Si hay raíz, la búsqueda la encuentra y termina; si no, sigue para siempre. Para un polinomio de una variable se pueden acotar las raíces y convertir la búsqueda en un algoritmo; para polinomios de varias variables (el décimo problema de Hilbert), Matiyasévich demostró en 1970 que no existe ningún algoritmo.

**Enumeradores.** Otra forma de ver los lenguajes semidecidibles: un **enumerador** es una MT que, sin entrada, escribe una lista, posiblemente infinita, de cadenas. Un lenguaje es recursivamente enumerable si y solo si algún enumerador lista exactamente sus cadenas; de ahí el nombre. Para construir el enumerador a partir de un reconocedor $M,$ se simula $M$ con las cadenas $w_1, w_2, \ldots$ en orden canónico **intercalando** las ejecuciones: $1$ paso con $w_1;$ luego $2$ pasos con $w_1$ y $w_2;$ luego $3$ pasos con $w_1, w_2, w_3;$ y así. Cada cadena que $M$ acepta se lista en algún momento, aunque $M$ cicle con otras.

### Implementación en Python

El programa implementa la máquina de la resta propia, la comprueba con todos los pares $m, n \leq 7$ y cuenta los pasos.

```python
BLANCO = '_'

class MT:
    """Máquina de Turing determinista de una cinta, infinita en ambas direcciones.

    delta: dict (estado, símbolo) -> (estado, símbolo a escribir, movimiento 'L', 'R' o 'S').
    La máquina se detiene al entrar a un estado de aceptación o de rechazo,
    o cuando no hay transición (y entonces rechaza)."""

    def __init__(self, delta, inicial, aceptacion=(), rechazo=()):
        self.delta, self.q0 = delta, inicial
        self.F, self.R = set(aceptacion), set(rechazo)

    def ejecutar(self, w, max_pasos=10_000, traza=False):
        cinta = dict(enumerate(w))
        q, cabeza, pasos, configs = self.q0, 0, 0, []
        while True:
            if traza:
                configs.append(self.configuracion(cinta, q, cabeza))
            if q in self.F or q in self.R:
                break
            simbolo = cinta.get(cabeza, BLANCO)
            if (q, simbolo) not in self.delta or pasos >= max_pasos:
                break
            q, escribir, mov = self.delta[(q, simbolo)]
            cinta[cabeza] = escribir
            cabeza += {'L': -1, 'R': 1, 'S': 0}[mov]
            pasos += 1
        contenido = ''.join(cinta.get(i, BLANCO) for i in range(min(cinta, default=0), max(cinta, default=0) + 1))
        return {'acepta': q in self.F, 'estado': q, 'pasos': pasos,
                'cinta': contenido.strip(BLANCO), 'traza': configs}

    @staticmethod
    def configuracion(cinta, q, cabeza):
        """Descripción instantánea u q v: la cabeza lee el primer símbolo de v."""
        usadas = [i for i, s in cinta.items() if s != BLANCO] + [cabeza]
        izq, der = min(usadas), max(usadas)
        u = ''.join(cinta.get(i, BLANCO) for i in range(izq, cabeza))
        v = ''.join(cinta.get(i, BLANCO) for i in range(cabeza, der + 1))
        return f"{u} {q} {v}".strip()

# Resta propia en unario: 0^m 1 0^n  ->  0^(m ∸ n), donde m ∸ n = max(m - n, 0)
resta = MT({
    ('q0', '0'): ('q1', '_', 'R'),   # quitar un 0 de m
    ('q0', '1'): ('q5', '_', 'R'),   # m se agotó: el resultado es 0, borrar todo
    ('q1', '0'): ('q1', '0', 'R'),
    ('q1', '1'): ('q2', '1', 'R'),
    ('q2', '1'): ('q2', '1', 'R'),   # ceros de n ya cancelados (escritos como 1)
    ('q2', '0'): ('q3', '1', 'L'),   # cancelar un 0 de n
    ('q2', '_'): ('q4', '_', 'L'),   # n se agotó: el 0 quitado en esta ronda sobra
    ('q3', '0'): ('q3', '0', 'L'),   # regresar al principio
    ('q3', '1'): ('q3', '1', 'L'),
    ('q3', '_'): ('q0', '_', 'R'),
    ('q4', '1'): ('q4', '_', 'L'),   # borrar los 1
    ('q4', '0'): ('q4', '0', 'L'),
    ('q4', '_'): ('fin', '0', 'S'),  # devolver el 0 quitado
    ('q5', '0'): ('q5', '_', 'R'),
    ('q5', '1'): ('q5', '_', 'R'),
    ('q5', '_'): ('fin', '_', 'S'),
}, 'q0', aceptacion={'fin'})

def f(m, n):
    r = resta.ejecutar('0' * m + '1' + '0' * n)
    return len(r['cinta']), r['pasos']

print(all(f(m, n)[0] == max(m - n, 0) for m in range(8) for n in range(8)))
for m, n in [(5, 2), (2, 5), (3, 3), (10, 4)]:
    print(f"{m} ∸ {n} = {f(m, n)[0]}  ({f(m, n)[1]} pasos)")
```

Salida:

```text
True
5 ∸ 2 = 3  (39 pasos)
2 ∸ 5 = 0  (21 pasos)
3 ∸ 3 = 0  (32 pasos)
10 ∸ 4 = 6  (115 pasos)
```

Cada ronda recorre la cinta de ida y vuelta, así que el número de pasos crece como $\min(m, n) \cdot (m + n).$

### Ejercicios Propuestos

1. **Simulación.** Escribe la computación de la máquina de la resta con la entrada $00100,$ es decir, $2 \mathbin{\dot{-}} 2.$

2. **Función.** Diseña una MT que calcule $f(n) = 2n$ en unario.

3. **Composición.** Usando la resta propia, describe una MT que decida si $m \geq n.$

4. **Semialgoritmo.** Explica por qué la búsqueda de raíces enteras de $x^2 - 2y^2 = 1$ termina, y por qué la de $x^2 - 2y^2 = 3$ no termina nunca.

5. **Enumeradores.** Explica por qué, para construir un enumerador a partir de un reconocedor, no basta con simular $M$ con $w_1,$ luego con $w_2,$ y así sucesivamente.

### Soluciones

**Ejercicio 1.** La computación tiene 18 pasos; con la notación del programa, en la que los blancos se escriben `_`:

```text
q0 00100 ⊢ q1 0100 ⊢ 0 q1 100 ⊢ 01 q2 00 ⊢ 0 q3 110 ⊢ q3 0110 ⊢ q3 _0110
⊢ q0 0110 ⊢ q1 110 ⊢ 1 q2 10 ⊢ 11 q2 0 ⊢ 1 q3 11 ⊢ q3 111 ⊢ q3 _111
⊢ q0 111 ⊢ q5 11 ⊢ q5 1 ⊢ q5 _ ⊢ fin _
```

En la primera ronda se borra un 0 de $m$ y se cancela el primer 0 de $n;$ en la segunda, lo mismo con los otros dos. En la tercera, $q_0$ encuentra el 1 porque $m$ se agotó, y $q_5$ borra todo: el resultado es la cinta vacía, $2 \mathbin{\dot{-}} 2 = 0.$

**Ejercicio 2.** Por cada 1 sin marcar: marcarlo y escribir un 1 nuevo al final de la cinta (después de un separador). Al terminar, borrar las marcas y el separador, desplazando. Otra forma, sin separador: duplicar cada símbolo con la técnica de desplazamiento.

**Ejercicio 3.** Calcular $n \mathbin{\dot{-}} m:$ es 0 si y solo si $m \geq n.$ La máquina ejecuta la resta con los argumentos intercambiados y luego mira si la cinta quedó vacía.

**Ejercicio 4.** La ecuación de Pell $x^2 - 2y^2 = 1$ tiene la solución $(3, 2),$ que la búsqueda encuentra pronto. En cambio, $x^2 - 2y^2 = 3$ no tiene soluciones enteras: módulo 8, $x^2 \in \{0, 1, 4\}$ y $2y^2 \in \{0, 2\},$ y ninguna diferencia da 3. La búsqueda no lo sabe y sigue para siempre; el argumento modular es un algoritmo para este caso particular, pero no hay uno que funcione para todas las ecuaciones.

**Ejercicio 5.** Si $M$ cicla con $w_1,$ la simulación nunca pasa a $w_2,$ y no se enumeraría ninguna otra cadena. Intercalar las simulaciones garantiza que cada una avance tanto como haga falta sin que ninguna bloquee a las demás.

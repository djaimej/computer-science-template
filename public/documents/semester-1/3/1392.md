# Introducción a las Ciencias de la Computación - Hilos de ejecución y multi-proceso (threads)

## 9.2 Mecanismos del lenguaje para hilos de ejecución.

---

Java incorporó los hilos desde su primera versión, como parte del lenguaje y no como una biblioteca externa. Con los años se agregaron abstracciones de más alto nivel que evitan manejar hilos individuales: los **ejecutores**, que administran conjuntos de hilos reutilizables, las **tareas con resultado** y, desde Java 21, los **hilos virtuales**. Esta página presenta los mecanismos en orden, de los más básicos a los recomendados para programas reales.

### 1. La clase `Thread` y la interfaz `Runnable`

La tarea que ejecutará un hilo se describe con un objeto `Runnable`, una interfaz funcional con un solo método, `void run()`. Hay tres formas equivalentes de crear un hilo:

```java
public class CrearHilos {
    static class Tarea implements Runnable {                 // 1. clase que implementa Runnable
        public void run() { System.out.println("tarea en " + Thread.currentThread().getName()); }
    }

    static class MiHilo extends Thread {                     // 2. subclase de Thread
        MiHilo() { super("hilo-subclase"); }
        @Override public void run() { System.out.println("subclase en " + getName()); }
    }

    public static void main(String[] args) throws InterruptedException {
        Thread a = new Thread(new Tarea(), "hilo-runnable");
        Thread b = new MiHilo();
        Thread c = new Thread(() -> System.out.println("lambda en " + Thread.currentThread().getName()),
                              "hilo-lambda");                // 3. expresión lambda
        a.start(); a.join();
        b.start(); b.join();
        c.start(); c.join();
    }
}
```

```text
tarea en hilo-runnable
subclase en hilo-subclase
lambda en hilo-lambda
```

Se prefiere implementar `Runnable`, normalmente con una lambda, en lugar de heredar de `Thread`: separa la **tarea** del **mecanismo** que la ejecuta, y deja libre la herencia para otra cosa.

**`start` y no `run`.** `start()` crea un nuevo hilo del sistema y ejecuta `run()` en él. Llamar `run()` directamente es una llamada a método común: se ejecuta en el hilo actual y no hay concurrencia. Además, un hilo solo puede iniciarse una vez; llamar `start()` de nuevo lanza `IllegalThreadStateException`.

### 2. Operaciones básicas

| Método                       | Efecto                                                                  |
| ---------------------------- | ----------------------------------------------------------------------- |
| `t.start()`                  | inicia la ejecución del hilo                                            |
| `t.join()`                   | el hilo actual espera a que `t` termine                                 |
| `Thread.sleep(ms)`           | suspende el hilo actual durante el tiempo indicado                      |
| `Thread.currentThread()`     | el hilo que está ejecutando esta instrucción                            |
| `t.interrupt()`              | solicita a `t` que se detenga (subtema 9.4)                             |
| `t.setDaemon(true)`          | lo marca como hilo de servicio: no impide que el programa termine        |
| `t.getState()`, `t.isAlive()` | consultas sobre su estado                                              |

`sleep` y `join` lanzan `InterruptedException`, una excepción verificada que indica que otro hilo pidió interrumpir la espera.

Un programa de Java termina cuando terminan **todos sus hilos que no son de servicio**, no cuando termina `main`. Los hilos de servicio (*daemon*) se usan para tareas auxiliares, como la recolección de basura, que no deben mantener vivo el programa.

### 3. Dividir un trabajo entre hilos

```java
public class SumaParalela {
    public static void main(String[] args) throws InterruptedException {
        int[] datos = new int[10_000_000];
        for (int i = 0; i < datos.length; i++) datos[i] = i % 100;

        int k = 4;                                         // número de hilos
        long[] parciales = new long[k];                    // cada hilo escribe en su casilla
        Thread[] hilos = new Thread[k];
        int bloque = datos.length / k;
        for (int h = 0; h < k; h++) {
            final int id = h;
            final int ini = h * bloque;
            final int fin = (h == k - 1) ? datos.length : ini + bloque;
            hilos[h] = new Thread(() -> {
                long s = 0;
                for (int i = ini; i < fin; i++) s += datos[i];
                parciales[id] = s;
            });
            hilos[h].start();
        }
        long total = 0;
        for (int h = 0; h < k; h++) {
            hilos[h].join();                               // esperar antes de leer su resultado
            total += parciales[h];
        }
        System.out.println(total);                         // 495000000
    }
}
```

Cada hilo escribe en una casilla **distinta** del arreglo `parciales`, así que no hay condición de carrera. El `join` es indispensable: además de esperar, garantiza que los valores escritos por el hilo sean visibles para quien lo esperó.

Las lambdas solo pueden usar variables locales que sean **efectivamente finales**, es decir, que no cambian después de asignarse. Por eso se copian `h`, `ini` y `fin` en variables nuevas en cada iteración.

### 4. Ejecutores y conjuntos de hilos

Crear un hilo por cada tarea tiene inconvenientes: cada hilo del sistema consume memoria, crear miles es lento, y es fácil olvidar esperarlos o manejar sus errores. Un **ejecutor** (`ExecutorService`) mantiene un **conjunto de hilos** (*thread pool*) reutilizables y una cola de tareas pendientes: el programa solo envía tareas y el ejecutor las reparte.

Las tareas que producen un resultado se describen con `Callable<T>`, cuyo método `call()` regresa un valor y puede lanzar excepciones. Al enviarla, el ejecutor regresa un `Future<T>`, una promesa del resultado que se obtiene con `get()`, esperando si aún no está listo:

```java
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.*;

public class ContarPrimos {
    static boolean esPrimo(int n) {
        if (n < 2) return false;
        for (int d = 2; (long) d * d <= n; d++) if (n % d == 0) return false;
        return true;
    }

    static long contar(int desde, int hasta) {
        long c = 0;
        for (int n = desde; n < hasta; n++) if (esPrimo(n)) c++;
        return c;
    }

    public static void main(String[] args) throws Exception {
        int limite = 2_000_000, partes = 8;
        ExecutorService ejecutor = Executors.newFixedThreadPool(Runtime.getRuntime().availableProcessors());
        try {
            List<Future<Long>> futuros = new ArrayList<>();
            for (int i = 0; i < partes; i++) {
                int desde = i * limite / partes, hasta = (i + 1) * limite / partes;
                Callable<Long> tarea = () -> contar(desde, hasta);
                futuros.add(ejecutor.submit(tarea));
            }
            long total = 0;
            for (Future<Long> f : futuros) total += f.get();     // espera cada resultado
            System.out.println("Primos menores que " + limite + ": " + total);
        } finally {
            ejecutor.shutdown();                                  // no acepta más tareas
        }
    }
}
```

```text
Primos menores que 2000000: 148933
```

Si una tarea lanza una excepción, `get()` la entrega envuelta en una `ExecutionException`, cuya causa es la original. Así los errores de los hilos no se pierden.

| Fábrica de `Executors`             | Comportamiento                                                  |
| ---------------------------------- | --------------------------------------------------------------- |
| `newFixedThreadPool(n)`            | $n$ hilos fijos; el tamaño natural para cálculos es el número de núcleos |
| `newCachedThreadPool()`            | crea hilos según se necesiten y reutiliza los ociosos           |
| `newSingleThreadExecutor()`        | un solo hilo: las tareas se ejecutan en orden                   |
| `newScheduledThreadPool(n)`        | permite programar tareas con retraso o periódicas               |
| `newVirtualThreadPerTaskExecutor()` | un hilo virtual por tarea, desde Java 21                      |

### 5. Hilos virtuales

Los hilos tradicionales de Java corresponden uno a uno con hilos del sistema operativo, que son costosos: un servidor no puede tener cientos de miles. Desde Java 21 existen los **hilos virtuales**: hilos ligeros administrados por la JVM, que se ejecutan sobre unos pocos hilos del sistema. Cuando un hilo virtual espera, por ejemplo una respuesta de la red, la JVM lo retira y usa el hilo del sistema para otro. Así se pueden crear millones:

```java
try (ExecutorService ej = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 100_000; i++) {
        ej.submit(() -> { Thread.sleep(1000); return null; });   // cien mil esperas simultáneas
    }
}   // close() espera a que terminen todas las tareas
```

Los hilos virtuales convienen para tareas que pasan la mayor parte del tiempo **esperando** entrada y salida. Para cálculos intensivos no ayudan: el límite sigue siendo el número de núcleos.

### 6. Paralelismo de alto nivel

Para muchas operaciones sobre colecciones, la biblioteca ofrece paralelismo sin manejar hilos ni ejecutores explícitamente:

```java
long primos = java.util.stream.IntStream.range(0, 2_000_000)
        .parallel()                          // reparte el rango entre los núcleos
        .filter(ContarPrimos::esPrimo)
        .count();
```

Por debajo, los flujos paralelos usan un ejecutor común con la estrategia **divide y vencerás** de *fork/join*: parten el trabajo recursivamente hasta que los pedazos son pequeños, los procesan en paralelo y combinan los resultados.

> **Conexión con CC.** La evolución de los mecanismos de Java, de hilos manuales a ejecutores, flujos paralelos y hilos virtuales, refleja una tendencia general: elevar el nivel de abstracción para que el programador describa **qué** se puede hacer en paralelo y deje al sistema decidir **cómo**. Otros lenguajes adoptan modelos distintos: Go usa *goroutines*, muy parecidas a los hilos virtuales, que se comunican por canales; Erlang usa procesos ligeros que no comparten memoria; JavaScript usa un solo hilo con un ciclo de eventos.

1. Cambie en `CrearHilos` las llamadas a `start()` por `run()`. ¿Qué nombre de hilo se imprime ahora? Explique.
2. Modifique `SumaParalela` para medir el tiempo con 1, 2, 4, 8 y 16 hilos. Grafique la aceleración y compárela con la ley de Amdahl del subtema 9.1.
3. Escriba un programa que busque en paralelo, con un `ExecutorService`, la palabra más frecuente en cada uno de varios archivos de texto, y luego la más frecuente en total.
4. Haga que una de las tareas de `ContarPrimos` lance una excepción y observe cómo se manifiesta en `get()`. Agregue el manejo adecuado.
5. Escriba una tarea periódica con `newScheduledThreadPool` que imprima la hora cada segundo durante cinco segundos y luego se detenga.
6. Compare el tiempo de crear 10 000 hilos tradicionales que duermen 100 ms contra 10 000 hilos virtuales que hacen lo mismo.

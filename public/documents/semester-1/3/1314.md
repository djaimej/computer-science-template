# Introducción a las Ciencias de la Computación - Conceptos generales de computación

## 1.4 Sistema binario y cambios de base.

---

Una computadora digital almacena todo con dispositivos de dos estados: un transistor que conduce o no, un capacitor cargado o descargado, una zona magnetizada en un sentido o en el otro. Por eso usa el sistema **binario**, con solo dos dígitos. Para los humanos, en cambio, resultan más cómodos el decimal y, al leer valores binarios largos, el **hexadecimal**. Este subtema explica los sistemas posicionales en general, cómo convertir entre bases y cómo se hace aritmética en binario.

### 1. Sistemas de numeración posicionales

En un sistema posicional de **base** $b \geq 2$ se usan los dígitos $0, 1, \ldots, b - 1$, y el valor de cada dígito depende de su posición. Un número con dígitos $d_{n-1} \ldots d_1 d_0$ vale

$$N = \sum_{i=0}^{n-1} d_i \cdot b^i = d_{n-1} b^{n-1} + \cdots + d_1 b + d_0$$

Para indicar la base se escribe como subíndice: $1011_2$, $755_8$, $2F_{16}$.

| Base | Nombre       | Dígitos                         | Uso en computación                                 |
| ---- | ------------ | ------------------------------- | -------------------------------------------------- |
| 2    | binario      | 0, 1                            | representación interna                              |
| 8    | octal        | 0 a 7                           | permisos de archivos en Unix (`chmod 755`)          |
| 10   | decimal      | 0 a 9                           | interacción con personas                            |
| 16   | hexadecimal  | 0 a 9 y A a F, con A = 10, …, F = 15 | direcciones de memoria, colores (`#FF8800`), bytes |

**Ejemplos de lectura:**

$$1011_2 = 1 \cdot 2^3 + 0 \cdot 2^2 + 1 \cdot 2^1 + 1 \cdot 2^0 = 8 + 0 + 2 + 1 = 11_{10}$$

$$2F_{16} = 2 \cdot 16 + 15 = 47_{10} \qquad 755_8 = 7 \cdot 64 + 5 \cdot 8 + 5 = 493_{10}$$

**Cuántos valores caben.** Con $n$ dígitos binarios, llamados **bits**, se representan $2^n$ valores distintos: los naturales de $0$ a $2^n - 1$. Un **byte** tiene 8 bits y representa $2^8 = 256$ valores, de 0 a 255.

| Bits | Valores           | Máximo sin signo            |
| ---- | ----------------- | --------------------------- |
| 4    | 16                | 15                          |
| 8    | 256               | 255                         |
| 16   | 65 536            | 65 535                      |
| 32   | $\approx 4.3 \times 10^{9}$  | 4 294 967 295    |
| 64   | $\approx 1.8 \times 10^{19}$ | $2^{64} - 1$     |

### 2. Conversión de una base cualquiera a decimal

Se aplica la fórmula de la sección 1. Una forma más eficiente, llamada **método de Horner**, recorre los dígitos de izquierda a derecha multiplicando lo acumulado por la base y sumando el siguiente dígito:

$$1101_2: \quad 1 \;\to\; 1 \cdot 2 + 1 = 3 \;\to\; 3 \cdot 2 + 0 = 6 \;\to\; 6 \cdot 2 + 1 = 13$$

Así se evita calcular potencias, y es como trabaja internamente una función que convierte texto a número.

### 3. Conversión de decimal a otra base

**Divisiones sucesivas.** Se divide el número entre la base, se anota el residuo y se repite con el cociente hasta llegar a 0. Los residuos, leídos **de abajo hacia arriba**, son los dígitos.

**Ejemplo:** $25_{10}$ a binario.

| División    | Cociente | Residuo |
| ----------- | -------- | ------- |
| $25 \div 2$ | 12       | 1       |
| $12 \div 2$ | 6        | 0       |
| $6 \div 2$  | 3        | 0       |
| $3 \div 2$  | 1        | 1       |
| $1 \div 2$  | 0        | 1       |

Leyendo los residuos de abajo hacia arriba, $25_{10} = 11001_2$. **Comprobación:** $16 + 8 + 1 = 25$.

El método funciona porque el residuo de dividir $N$ entre $b$ es precisamente el último dígito $d_0$, y el cociente es el número formado por los dígitos restantes.

**Ejemplo:** $500_{10}$ a hexadecimal: $500 = 31 \cdot 16 + 4$, $31 = 1 \cdot 16 + 15$, $1 = 0 \cdot 16 + 1$. Los residuos de abajo arriba son $1, 15, 4$, es decir, $500_{10} = 1F4_{16}$.

**Restando potencias.** Para números pequeños es más rápido restar la mayor potencia de 2 que quepa: $45 = 32 + 8 + 4 + 1$, así que $45_{10} = 101101_2$.

### 4. Binario, octal y hexadecimal

Como $8 = 2^3$ y $16 = 2^4$, cada dígito octal corresponde exactamente a 3 bits y cada dígito hexadecimal a 4 bits, llamados un **nibble**. La conversión no necesita pasar por el decimal: basta **agrupar** los bits desde la derecha.

| Hex | Binario | Hex | Binario |
| --- | ------- | --- | ------- |
| 0   | 0000    | 8   | 1000    |
| 1   | 0001    | 9   | 1001    |
| 2   | 0010    | A   | 1010    |
| 3   | 0011    | B   | 1011    |
| 4   | 0100    | C   | 1100    |
| 5   | 0101    | D   | 1101    |
| 6   | 0110    | E   | 1110    |
| 7   | 0111    | F   | 1111    |

**Ejemplos:**

$$1011\,0110\,1110_2 = B6E_{16} \qquad 10\,110\,110\,111_2 = 2667_8 \qquad 3A_{16} = 0011\,1010_2$$

Por eso el hexadecimal es la forma estándar de mostrar contenidos de memoria: un byte son exactamente dos dígitos hexadecimales, de `00` a `FF`.

### 5. Fracciones en binario

Las posiciones a la derecha del punto valen potencias negativas de la base: $0.101_2 = \frac{1}{2} + \frac{0}{4} + \frac{1}{8} = 0.625_{10}$.

Para convertir una fracción decimal a binario se **multiplica sucesivamente por 2** y se toma la parte entera de cada resultado como el siguiente dígito:

| Operación          | Resultado | Dígito |
| ------------------ | --------- | ------ |
| $0.375 \times 2$   | 0.75      | 0      |
| $0.75 \times 2$    | 1.5       | 1      |
| $0.5 \times 2$     | 1.0       | 1      |

Así $0.375_{10} = 0.011_2$. Pero con $0.1_{10}$ el proceso **nunca termina**: $0.1_{10} = 0.0\overline{0011}_2$, un número periódico, igual que $\frac{1}{3} = 0.333\ldots$ en decimal. Como la computadora guarda un número finito de bits, $0.1$ se almacena de forma aproximada. Esa es la razón por la que en casi todos los lenguajes `0.1 + 0.2 == 0.3` es falso. La representación de punto flotante se estudia en el subtema 1.5.

### 6. Aritmética binaria

**Suma.** Se suma columna por columna, de derecha a izquierda, con las reglas $0 + 0 = 0$, $0 + 1 = 1$, $1 + 1 = 10_2$ (se escribe 0 y se lleva 1) y $1 + 1 + 1 = 11_2$ (se escribe 1 y se lleva 1).

$$
\begin{array}{r}
1011_2 \\
+\;1101_2 \\ \hline
11000_2
\end{array}
\qquad
\text{en decimal: } 11 + 13 = 24
$$

**Resta.** Se presta de la columna siguiente como en decimal: $10_2 - 1_2 = 1_2$. En el hardware, la resta se hace sumando el **complemento a dos** del sustraendo, como se explica en el subtema 1.5.

**Multiplicación.** Es la más sencilla: cada producto parcial es una copia desplazada del multiplicando o cero. Para $101_2 \times 11_2$ se suman $101_2$ y $1010_2$, que da $1111_2$, es decir, $5 \times 3 = 15$.

**Desplazamientos.** Desplazar un número binario $k$ posiciones a la izquierda equivale a multiplicarlo por $2^k$, y a la derecha, a dividirlo entre $2^k$ descartando el residuo, igual que agregar o quitar ceros en decimal multiplica o divide entre 10.

$$1010_2 \ll 1 = 10100_2 \quad (10 \cdot 2 = 20) \qquad 10111_2 \gg 2 = 101_2 \quad (23 \div 4 = 5)$$

**Desbordamiento.** Si el resultado necesita más bits de los disponibles, el bit sobrante se pierde. Con 8 bits sin signo, $255 + 1$ da $0$: el contador "da la vuelta", como el odómetro de un auto.

### 7. Bases en Java

```java
public class Bases {
    public static void main(String[] args) {
        int a = 0b1011;          // literal binario: 11
        int b = 0x2F;            // literal hexadecimal: 47
        int c = 0755;            // literal octal: 493 (el 0 inicial indica octal)

        System.out.println(a + " " + b + " " + c);
        System.out.println(Integer.toBinaryString(25));   // 11001
        System.out.println(Integer.toHexString(500));     // 1f4
        System.out.println(Integer.parseInt("1101", 2));  // 13
        System.out.println(Integer.parseInt("FF", 16));   // 255
        System.out.println(10 << 1);                      // 20
        System.out.println(23 >> 2);                      // 5
        System.out.println(aBase(500, 16));               // 1F4
    }

    /** Convierte un natural a la base indicada (entre 2 y 16) por divisiones sucesivas. */
    static String aBase(int n, int base) {
        if (n == 0) return "0";
        String digitos = "0123456789ABCDEF";
        StringBuilder sb = new StringBuilder();
        while (n > 0) {
            sb.append(digitos.charAt(n % base));   // residuo: siguiente digito
            n /= base;                              // cociente
        }
        return sb.reverse().toString();            // los residuos se leen al reves
    }
}
```

Cuidado con el literal `0755`: en Java, un número que empieza con 0 se interpreta en octal, lo cual ha causado errores en programas que guardaban, por ejemplo, códigos postales con ceros a la izquierda.

> **Conexión con CC.** Las operaciones de bits aparecen constantemente en programación de bajo nivel: los permisos de Unix `rwxr-xr-x` son los bits de $755_8$, una dirección IPv4 es un número de 32 bits escrito en cuatro bytes decimales, y un color en una página web, como `#1E90FF`, son tres bytes en hexadecimal para rojo, verde y azul.

### Ejercicios propuestos

1. Convierta $47_{10}$, $200_{10}$ y $1000_{10}$ a binario, octal y hexadecimal.
2. Convierta $110111001_2$ a octal y a hexadecimal agrupando bits, y verifique pasando ambos a decimal.
3. Realice $101101_2 + 11011_2$ y $1101_2 \times 101_2$, y compruebe los resultados en decimal.
4. Convierta $0.8125_{10}$ y $0.2_{10}$ a binario. ¿Cuál de los dos tiene representación finita? Explique qué fracciones tienen representación binaria finita.
5. ¿Cuál es el mayor número que se puede representar con 12 bits sin signo? ¿Cuántos dígitos hexadecimales hacen falta para escribirlo?
6. Modifique el método `aBase` para que acepte bases hasta 36, usando las letras del alfabeto como dígitos, y escriba el método inverso que convierte una cadena en cualquier base a `int` usando el método de Horner.

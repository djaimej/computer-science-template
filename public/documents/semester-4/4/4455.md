# Organización y Arquitectura de Computadoras - Diseño del conjunto de instrucciones

## 5.5 Formatos de instrucción y su proceso de ejecución

---

### 1. Definición

Un **formato de instrucción** es la estructura binaria que define cómo se codifica una instrucción en lenguaje máquina.
Incluye:

- **Código de operación (opcode):** indica la operación a realizar.
- **Campos de operandos:** registros o direcciones de memoria involucradas.
- **Campo de direccionamiento:** define cómo localizar los operandos.
- **Bits adicionales:** para control, banderas o desplazamientos.

-> La definición de los formatos de instrucción depende de:

- El **ISA**.
- El número de **registros disponibles**.
- Los **modos de direccionamiento soportados**.

### 2. Tipos de formatos de instrucción

#### 2.1 Formato de longitud fija

- Todas las instrucciones tienen el mismo tamaño en bits.
- Ejemplo: MIPS (32 bits por instrucción).
- Ventaja: fácil decodificación.
- Desventaja: puede desperdiciar espacio.

#### 2.2 Formato de longitud variable

- Instrucciones con diferentes tamaños.
- Ejemplo: x86 (1 a 15 bytes).
- Ventaja: alta flexibilidad.
- Desventaja: decodificación más compleja.

### 3. Ejemplo: formatos de instrucción en MIPS

MIPS usa **instrucciones de 32 bits** con 3 formatos:

1. **Formato R (Register):**
   Para operaciones aritméticas/lógicas entre registros.

   ```
   | opcode (6) | rs (5) | rt (5) | rd (5) | shamt (5) | funct (6) |
   ```

   Ejemplo:

   ```asm
   ADD R1, R2, R3   ; R1 = R2 + R3
   ```

2. **Formato I (Immediate):**
   Para operaciones con constantes y accesos a memoria.

   ```
   | opcode (6) | rs (5) | rt (5) | immediate (16) |
   ```

   Ejemplo:

   ```asm
   LW R1, 8(R2)     ; R1 = M[R2 + 8]
   ```

3. **Formato J (Jump):**
   Para saltos largos en el programa.

   ```
   | opcode (6) | address (26) |
   ```

   Ejemplo:

   ```asm
   J etiqueta
   ```

### 4. Proceso de ejecución de una instrucción

El ciclo de ejecución de una instrucción se compone de varias **etapas del datapath**:

1. **IF (Instruction Fetch):** buscar la instrucción en memoria.
2. **ID (Instruction Decode):** decodificar la instrucción y leer registros.
3. **EX (Execute):** realizar operación aritmética/lógica o calcular dirección efectiva.
4. **MEM (Memory Access):** acceso a memoria si es necesario.
5. **WB (Write Back):** escribir resultados en registros.

-> Fórmula del tiempo de ejecución:

$$
T_{ejec} = N_{ins} \times CPI \times T_{ciclo}
$$

### 5. Ejemplo en código

#### Instrucción:

```asm
LW R1, 8(R2)
```

#### Proceso paso a paso:

1. **IF:** Se obtiene el código binario de `LW` desde memoria.
2. **ID:** Se identifican campos: `opcode=LW`, `base=R2`, `rt=R1`, `offset=8`.
3. **EX:** Se calcula la dirección efectiva $EA = R2 + 8.$
4. **MEM:** Se accede a memoria en la dirección $EA.$
5. **WB:** Se guarda el valor leído en `R1`.

### 6. Diagrama del ciclo de instrucción

```mermaid
graph LR
    A[Fetch: IF] --> B[Decode: ID]
    B --> C[Execute: EX]
    C --> D[Memory: MEM]
    D --> E[Write Back: WB]
```

### 7. Ejemplo Resuelto

**Problema:** ¿Cuál es la dirección efectiva de la instrucción `LW R1, 12(R3)` si $R3 = 1000?$

**Solución:**

$$ EA = R3 + offset = 1000 + 12 = 1012 $$

-> El operando cargado es $M[1012]$ y se guarda en `R1`.

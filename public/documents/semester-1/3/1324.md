## 2.4 Entrada y salida: métodos y parámetros/argumentos; archivos de entrada y salida simples.

---

Un programa intercambia información en dos niveles. **Dentro** del programa, los métodos reciben datos a través de sus **parámetros** y entregan resultados con `return`. **Hacia afuera**, el programa lee datos del teclado, de la línea de comandos o de archivos, y escribe resultados en la pantalla o en otros archivos. Este subtema cubre ambos niveles con lo necesario para escribir programas completos; el tema 8 profundiza en archivos.

### 1. Métodos: la entrada y salida de un fragmento de código

Un método tiene una **firma**: nombre, tipos de sus parámetros y tipo de regreso.

```java
public static double promedio(double a, double b, double c) {
    return (a + b + c) / 3;
}
```

- Los **parámetros** son las variables declaradas en la firma: `a`, `b` y `c`. Son la entrada del método.
- Los **argumentos** son los valores concretos con los que se invoca: en `promedio(8, 9.5, 10)` los argumentos son `8`, `9.5` y `10`.
- El **valor de regreso** es la salida. Un método `void` no regresa nada y se usa por sus efectos, como imprimir o modificar un objeto.

Al invocar el método, cada argumento se evalúa y su valor se copia en el parámetro correspondiente. Por eso los argumentos deben coincidir en número, orden y tipo con los parámetros.

### 2. Paso de parámetros en Java: siempre por valor

En Java **todo** se pasa por valor: el parámetro recibe una **copia** del valor del argumento. Las consecuencias dependen del tipo:

- Si el argumento es de un **tipo primitivo** (`int`, `double`, `boolean`, …), el método recibe una copia del número y no puede cambiar la variable original.
- Si el argumento es un **objeto**, lo que se copia es la **referencia**: el parámetro apunta al **mismo** objeto. El método puede modificar el estado del objeto, pero si reasigna el parámetro a otro objeto, la variable original no cambia.

```java
public class PasoDeParametros {
    static void incrementar(int n) {
        n = n + 1;                    // modifica la copia
    }

    static void agregarPunto(StringBuilder sb) {
        sb.append(".");               // modifica el objeto compartido
    }

    static void reemplazar(StringBuilder sb) {
        sb = new StringBuilder("otro"); // solo cambia la copia de la referencia
    }

    public static void main(String[] args) {
        int x = 5;
        incrementar(x);
        System.out.println(x);        // 5

        StringBuilder texto = new StringBuilder("hola");
        agregarPunto(texto);
        System.out.println(texto);    // hola.
        reemplazar(texto);
        System.out.println(texto);    // hola.
    }
}
```

Este comportamiento se entiende con el modelo de memoria del tema 6: las variables de objeto guardan direcciones, y copiar una dirección no copia el objeto.

### 3. Sobrecarga y número variable de argumentos

**Sobrecarga.** Varios métodos de una clase pueden tener el mismo nombre si sus listas de parámetros difieren. El compilador elige cuál llamar según los argumentos:

```java
static int maximo(int a, int b) { return a > b ? a : b; }
static double maximo(double a, double b) { return a > b ? a : b; }
static int maximo(int a, int b, int c) { return maximo(maximo(a, b), c); }
```

`System.out.println` es un ejemplo: tiene versiones para `int`, `double`, `String`, `Object` y otros tipos.

**Argumentos variables.** Con `...` un método acepta cualquier número de argumentos de un tipo, que recibe como arreglo:

```java
static double promedio(double... valores) {
    if (valores.length == 0) throw new IllegalArgumentException("Sin valores");
    double suma = 0;
    for (double v : valores) suma += v;
    return suma / valores.length;
}
// promedio(8, 9) y promedio(7, 8, 9, 10) son ambas válidas
```

### 4. Entrada y salida por consola

**Salida.** `System.out.println` imprime y salta de línea; `print` no salta; `printf` permite dar formato:

```java
String nombre = "Ana";
double promedio = 9.456;
System.out.printf("%s tiene promedio %.2f%n", nombre, promedio);  // Ana tiene promedio 9.46
System.out.printf("%5d|%-8s|%08.3f%n", 42, "hola", 3.14159);       //    42|hola    |0003.142
```

| Especificador | Significado                             |
| ------------- | --------------------------------------- |
| `%d`          | entero                                  |
| `%f`, `%.2f`  | número real, con dos decimales           |
| `%s`          | cadena, o cualquier objeto con su `toString` |
| `%n`          | salto de línea del sistema operativo     |
| `%5d`, `%-8s` | ancho mínimo, alineado a la derecha o a la izquierda |

Los mensajes de error se escriben en `System.err`, un flujo separado que puede redirigirse por su cuenta.

**Entrada.** La clase `Scanner` lee y convierte datos de la entrada estándar:

```java
import java.util.Scanner;

public class Promedios {
    public static void main(String[] args) {
        Scanner entrada = new Scanner(System.in);
        System.out.print("¿Cuántas calificaciones? ");
        int n = entrada.nextInt();
        double suma = 0;
        for (int i = 1; i <= n; i++) {
            System.out.print("Calificación " + i + ": ");
            suma += entrada.nextDouble();
        }
        System.out.printf("Promedio: %.2f%n", suma / n);
    }
}
```

Un detalle frecuente: `nextInt` no consume el salto de línea que sigue al número, así que un `nextLine` inmediatamente después regresa una cadena vacía. Una solución es leer siempre líneas completas con `nextLine` y convertirlas con `Integer.parseInt`.

**Argumentos de línea de comandos.** Los valores escritos después del nombre del programa llegan al arreglo `args` de `main`:

```text
java Saludo Ana 21      →  args[0] = "Ana", args[1] = "21"
```

Siempre llegan como cadenas; para usarlos como números hay que convertirlos.

### 5. Archivos de texto simples

La forma más directa de leer y escribir archivos de texto en Java moderno usa la clase `Files`:

```java
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.ArrayList;
import java.util.List;

public class ResumenCalificaciones {
    public static void main(String[] args) throws IOException {
        Path entrada = Path.of("calificaciones.txt");
        Files.write(entrada, List.of("Ana,9.5", "Luis,7.0", "Eva,8.5"));   // prepara un ejemplo

        List<String> salida = new ArrayList<>();
        double suma = 0;
        int n = 0;
        for (String linea : Files.readAllLines(entrada)) {
            String[] partes = linea.split(",");
            double calif = Double.parseDouble(partes[1]);
            suma += calif;
            n++;
            salida.add(partes[0] + (calif >= 8 ? " aprobado con distinción" : " aprobado"));
        }
        salida.add(String.format("Promedio del grupo: %.2f", suma / n));
        Files.write(Path.of("resumen.txt"), salida);
        System.out.println(String.join(System.lineSeparator(), Files.readAllLines(Path.of("resumen.txt"))));
    }
}
```

Para archivos grandes no conviene cargar todo en memoria: se leen línea por línea con un `BufferedReader`. Se usa `try` con recursos para garantizar que el archivo se cierre aunque ocurra un error:

```java
try (var lector = Files.newBufferedReader(Path.of("datos.txt"))) {
    String linea;
    while ((linea = lector.readLine()) != null) {
        System.out.println(linea.toUpperCase());
    }
}
```

**Errores de entrada y salida.** Las operaciones con archivos pueden fallar por causas ajenas al programa: el archivo no existe, no hay permiso o el disco está lleno. Java las señala con una `IOException`, que el compilador obliga a manejar o declarar con `throws`. El manejo de errores se estudia en el tema 7.

> **Conexión con CC.** El modelo de entrada estándar, salida estándar y salida de errores proviene de Unix y permite **componer programas**: la salida de uno se conecta a la entrada de otro con una tubería, como en `java Generador | java Filtro > resultado.txt`. Diseñar programas que lean de la entrada estándar y escriban en la salida estándar los hace reutilizables de esta forma.

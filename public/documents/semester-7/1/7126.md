# Compiladores - Análisis léxico

## 2.6 Herramientas automáticas para la construcción de analizadores léxicos.

---

Un **generador de analizadores léxicos** recibe una especificación, una lista de expresiones regulares, cada una con una **acción**, y produce el código de un analizador que, al reconocer el lexema más largo de alguna expresión, ejecuta su acción. La herramienta implementa los algoritmos de los temas 2.3 y 2.4, de modo que quien escribe la especificación solo piensa en los tokens. Este tema presenta flex, el sucesor libre de lex, con su integración con bison, y JFlex, ANTLR y otras herramientas, con ejemplos reales generados y ejecutados.

### Estructura de una especificación de flex

Un archivo `.l` tiene tres secciones separadas por `%%`:

```lex
%{
/* declaraciones de C que se copian al inicio de lex.yy.c */
#include <stdio.h>
%}
DIGITO   [0-9]
%option noyywrap
%%
{DIGITO}+                { printf("ENTERO %s\n", yytext); }
[A-Za-z_][A-Za-z0-9_]*   { printf("ID %s\n", yytext); }
[ \t\n]+                 ;  /* sin acción: se descarta */
.                        { printf("ILEGAL %s\n", yytext); }
%%
int main(void) { yylex(); return 0; }
```

- La primera sección tiene código de C entre `%{` y `%}`, **definiciones** con nombre, como `DIGITO`, y opciones.
- La segunda tiene las **reglas**: una expresión al inicio de la línea y una acción de C. Dentro de la acción, `yytext` es el lexema y `yyleng` su longitud; la acción puede devolver un token con `return`, y entonces `yylex()` termina y la siguiente llamada continúa donde se quedó.
- La tercera es código de C que se copia al final.

Flex aplica las dos reglas de los temas anteriores: el **lexema más largo** y, en un empate, la **primera regla** de la lista. Por eso las palabras reservadas van antes del identificador y la regla `.` al final, para reportar cualquier carácter que no reconozcan las demás.

### Herramientas de flex para el contexto

- **Condiciones de inicio:** `%x NOMBRE` declara un modo exclusivo; una regla `<NOMBRE>r` solo se aplica en ese modo, y `BEGIN(NOMBRE)` cambia de modo. Sirven para las cadenas, los comentarios y el inicio de línea en lenguajes con sangría.
- **Contexto posterior:** `r/s` reconoce `r` solo si lo sigue `s`, sin consumir `s`.
- **`yyless(n)`** devuelve a la entrada todo menos los primeros `n` caracteres del lexema, y **`yymore()`** concatena el siguiente lexema con el actual.
- **`<<EOF>>`** es una regla para el fin del archivo, útil para cerrar los bloques pendientes o reportar un comentario sin cerrar.

### Integración con bison

Bison genera el analizador sintáctico y un archivo `parser.tab.h` con los números de los tokens y la unión `YYSTYPE` de sus atributos; el analizador léxico lo incluye, asigna el atributo a `yylval` y devuelve el token. El analizador sintáctico llama a `yylex()` cada vez que necesita un token.

```mermaid
flowchart LR
    L["lexer.l"] -->|"flex"| C1["lex.yy.c"]
    Y["parser.y"] -->|"bison -d"| C2["parser.tab.c"]
    Y -->|"bison -d"| H["parser.tab.h: tokens y YYSTYPE"]
    H --> C1
    C1 --> G["gcc"]
    C2 --> G
    G --> E["Ejecutable: yyparse llama a yylex"]
```

Un fragmento de un analizador léxico para bison:

```lex
%{
#include "parser.tab.h"
%}
%option noyywrap
%%
[0-9]+                 { yylval.ival = atoi(yytext); return ENTERO; }
[A-Za-z_][A-Za-z0-9_]* { yylval.sval = strdup(yytext); return IDENTIFICADOR; }
"=="                   { return IGUAL; }
[-+*/=;()]             { return yytext[0]; }   /* los tokens de un carácter pueden ser el carácter */
[ \t\n]+               ;
.                      { fprintf(stderr, "carácter ilegal '%s'\n", yytext); }
```

### Cómo funciona flex por dentro

Flex construye un AFN con todas las reglas, lo convierte en un AFD, en el que cada estado de aceptación recuerda la primera regla que acepta, lo minimiza y emite tablas comprimidas con un intérprete en `lex.yy.c`. Las opciones `-C` eligen el compromiso entre tamaño y velocidad: `-Ce` agrupa los caracteres en **clases de equivalencia**, `-Cm` agrupa además las clases en **metaclases**, y `-Cf` o `-CF` generan tablas completas, sin compresión, más grandes y más rápidas. La compresión por omisión, `-Cem`, usa el esquema de **filas desplazadas**: las filas de la tabla se superponen en un solo arreglo, aprovechando que la mayoría de sus entradas están vacías o se repiten.

### Otras herramientas

| Herramienta | Lenguaje generado | Características |
| ----------- | ----------------- | --------------- |
| lex, flex | C, C++ | el estándar de UNIX y POSIX; tablas comprimidas; se integra con yacc y bison |
| JFlex | Java | Unicode completo, condiciones de inicio, se integra con CUP y BYACC/J |
| ANTLR 4 | Java, Python, C#, JavaScript, Go y otros | una sola gramática para los analizadores léxico y sintáctico; **modos** léxicos; `-> skip` y canales para los comentarios |
| re2c | C, C++, Go, Rust | genera código dirigido, sin tablas; muy rápido; lo usan PHP y Ninja |
| Ragel | C, C++, Go, Java y otros | máquinas de estados con acciones en las transiciones |
| PLY y SLY | Python | analizadores léxicos y sintácticos con expresiones de `re` |
| Logos | Rust | genera el analizador al compilar, con macros |

%option noyywrap nounput noinput
%{
#include <stdio.h>
static int pila[128] = {0}, tope = 0, parens = 0, error = 0, linea = 1;
static void emite(const char *t, const char *v) { printf("%s %s\n", t, v); }
%}
%x INICIO_LINEA
DIG      [0-9]
EXP      [eE][+-]?{DIG}+
NUMERO   0[xX][0-9a-fA-F]+|0[bB][01]+|{DIG}+(\.{DIG}*)?{EXP}?|\.{DIG}+{EXP}?
CADENA   \"([^"\\\n]|\\.)*\"|'([^'\\\n]|\\.)*'
RESERV   def|return|if|elif|else|while|for|in|and|or|not|True|False|None

<INICIO_LINEA>[ ]*"#"[^\n]*\n   { linea++; }                  /* línea con solo un comentario */
<INICIO_LINEA>[ ]*[^ \n#]       { yyless(yyleng - 1);          /* devuelve el primer carácter */

                                  if (yyleng > pila[tope]) { pila[++tope] = yyleng; emite("INDENT", ""); }

                                      if (yyleng != pila[tope]) { fprintf(stderr, "línea %d: sangría inconsistente\n", linea); error = 1; }
                                  } }
\n                              { linea++; if (parens == 0) { emite("NEWLINE", "\\n"); BEGIN(INICIO_LINEA); } }
\\\n                            { linea++; }                  /* unión explícita de líneas */
[ \t]+                          ;
"#"[^\n]*                       ;

[A-Za-z_][A-Za-z0-9_]*          { emite("NAME", yytext); }
{NUMERO}                        { emite("NUMBER", yytext); }
{CADENA}                        { emite("STRING", yytext); }

[)\]]                           { parens--; emite("OP", yytext); }

.                               { fprintf(stderr, "línea %d: carácter ilegal '%s'\n", linea, yytext); error = 1; }
<INITIAL,INICIO_LINEA><<EOF>>   { while (tope > 0) { tope--; emite("DEDENT", ""); } emite("ENDMARKER", ""); return 0; }
%%
int main(void) { BEGIN(INICIO_LINEA); yylex(); return error; }

%column
%type String

%{

### Soluciones

**Ejercicio 1.** La especificación usa una condición de inicio exclusiva, `INICIO_LINEA`, en la que el analizador entra después de cada salto de línea. Ahí, las líneas en blanco y las que solo tienen un comentario se descartan; en cualquier otra, la regla `[ ]*[^ \n#]` mide la sangría, devuelve el primer carácter con `yyless` y la compara con la **pila de sangrías**: si es mayor, la apila y emite `INDENT`; si es menor, desapila y emite un `DEDENT` por nivel hasta encontrar la misma, y si no la encuentra, reporta una sangría inconsistente. Un contador de paréntesis y corchetes abiertos implementa la **unión implícita de líneas**: dentro de `[1, 2,` el salto de línea no genera `NEWLINE`. La regla `<<EOF>>` cierra los bloques pendientes con `DEDENT`. El analizador generado produce 70 tokens para el programa de prueba, y, tomando las palabras reservadas como `NAME`, la secuencia es **idéntica** a la del módulo `tokenize` de Python, incluidos los `INDENT` y `DEDENT` del ciclo con la lista partida en dos líneas. Los tres errores, la sangría inconsistente, la cadena sin cerrar y el carácter ilegal, se reportan con su línea.

**Ejercicio 2.** Con el programa repetido 3 000 veces, 678 000 caracteres, ambos analizadores producen los mismos 207 001 tokens, y el generado por flex, en C, es más de 5 veces más rápido que `tokenize`, aun contando el arranque del proceso; en esta máquina la diferencia es mucho mayor. La comparación justa entre un analizador escrito a mano y uno generado debe hacerse **en el mismo lenguaje**: en C, un analizador a mano bien escrito, como los de GCC y Clang, es comparable o más rápido que uno de flex, y uno de re2c compite con ambos. Para medir, se repite cada análisis varias veces, se toma la mediana y se varía el tamaño, para comprobar que el tiempo crece linealmente; el `tokenize` de Python es más lento porque cada token pasa por expresiones de `re` y crea un objeto de Python.

**Ejercicio 3.** La especificación de JFlex reconoce los hexadecimales y los binarios con sus propias reglas, antes que los decimales, y convierte el valor con `Long.parseLong` en la base correspondiente, de modo que `0x1A3F` produce 6719 y `0b1010` produce 10. Las cadenas usan un estado `CADENA`: la comilla de apertura guarda la posición e inicia un `StringBuilder`; cada secuencia de escape agrega su carácter, incluida `é`, y la comilla de cierre devuelve el token con el valor ya traducido, de 14 caracteres en el ejemplo. Una secuencia inválida, como `\q`, se reporta y la cadena continúa, y una cadena sin cerrar se reporta en la posición de su comilla de apertura, tanto si termina la línea como si termina el archivo, con la directiva `%eofval`. Las posiciones salen de `%line` y `%column`, que JFlex cuenta desde 0.

**Ejercicio 4.** La gramática de ANTLR tiene la estructura del analizador descendente del tema 2.3, de menor a mayor precedencia: alternativa, concatenación, repetición con sus cuantificadores, y átomo, que puede ser un grupo, una clase, el punto, un escape o un literal. Las reglas en mayúsculas son las **léxicas**, y las de minúsculas las sintácticas; ANTLR genera los dos analizadores a partir del mismo archivo. El árbol de `(a|b)*abb` muestra la cerradura aplicada al grupo y la concatenación de los cuatro factores, y el de `[0-9]{3}` la clase con su rango y el cuantificador. Con `a(b|`, ANTLR reporta "missing ')'", **inserta** el token que falta, una de sus estrategias de recuperación, y construye el árbol de todos modos.

**Ejercicio 5.** El resaltado necesita la **clase** y la **posición** de cada token; el programa ubica los lexemas en el texto, que llegan en orden, y los envuelve en elementos `span` con una clase de CSS por tipo de token. Un editor real tiene requisitos adicionales: **análisis incremental**, para no volver a analizar todo el archivo con cada tecla, lo que se logra guardando el estado del autómata al inicio de cada línea y reanalizando desde la línea modificada hasta que el estado coincida; **tolerancia a errores**, porque el texto casi siempre está incompleto, y la integración con el protocolo de servidores de lenguaje, LSP, cuyos *semantic tokens* comunican las clases al editor. Los editores modernos usan gramáticas de TextMate, que son expresiones regulares con estados, o tree-sitter, un generador de analizadores incrementales.

**Ejercicio 6.** Con gcc 13, el tamaño del código y los datos del objeto compilado varía así:

| Opción | Bytes | Compresión |
| ------ | ----- | ---------- |
| `-Cem` | 10 550 | clases y metaclases, la opción por omisión |
| `-Ce` | 11 518 | clases de equivalencia |
| `-Cm` | 12 950 | metaclases |
| `-Cfe` | 17 092 | tablas completas sobre las clases |
| `-CFe` | 18 856 | tablas completas rápidas sobre las clases |
| `-C` | 20 006 | solo filas desplazadas |
| `-CF` | 32 564 | tablas completas rápidas |
| `-Cf` | 32 940 | tablas completas, una columna por carácter |

Las ocho versiones producen exactamente la misma salida, porque la compresión no cambia el autómata. Las tablas completas triplican el tamaño a cambio de eliminar indirecciones en el ciclo interno; para una especificación pequeña como esta, todas caben en la caché, y la diferencia de velocidad es pequeña, mientras que en especificaciones grandes las tablas completas pueden ocupar cientos de kilobytes.

El ejemplo completo del material original no podía generarse: en flex, la clase `[+\\-*/]` contiene el rango de `\` a `*`, que va hacia atrás, y flex la rechaza con "negative range in character class", y ANTLR rechaza la misma clase en su gramática; bison rechaza `declaracion+`, porque no admite el operador `+` de las gramáticas extendidas, y hay que escribir una regla recursiva. Las acciones imprimían `"\\n"`, que muestra una barra y una n en lugar del salto de línea, y la regla de los comentarios de ANTLR, `'//' ~[\\n]*`, termina en la primera barra invertida o letra n, en lugar del fin de línea. El ejemplo de JFlex usaba `new Integer(...)` y `new Double(...)`, obsoletos desde Java 9 y marcados para eliminación.

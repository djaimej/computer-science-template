# Estructuras Discretas - Inducción y recursión

## 3.3 Inducción estructural: principios de inducción estructural, dualidad entre inducción y recursión, ejemplos de demostración en diversas estructuras.

---

La inducción sobre los naturales funciona porque todo natural se construye a partir de $0$ aplicando el sucesor. Las listas, los árboles y las fórmulas también se construyen a partir de casos base aplicando reglas, así que admiten el mismo tipo de demostración. La **inducción estructural** sigue la forma de la definición recursiva: un caso por cada cláusula base y un caso por cada regla de construcción. Es la técnica con la que se demuestra que las funciones del subtema 3.2 hacen lo que se espera de ellas.

### 1. El principio

Sea $A$ un conjunto definido recursivamente y $P$ una propiedad de sus elementos. Si

1. **(Base)** $P(b)$ se cumple para cada elemento $b$ dado por las cláusulas base, y
2. **(Paso)** para cada regla que construye $x$ a partir de $y_1, \ldots, y_k \in A$, si $P(y_1), \ldots, P(y_k)$ se cumplen, entonces $P(x)$ se cumple,

entonces $P(x)$ se cumple para todo $x \in A$. Las suposiciones $P(y_i)$ son las **hipótesis de inducción**, una por cada componente recursiva.

**¿Por qué es válido?** Sea $B = \{x \in A \mid P(x)\}$. Las condiciones 1 y 2 dicen que $B$ contiene los elementos base y es cerrado bajo las reglas. Como $A$ es el **menor** conjunto con esas dos características, por la cláusula de cierre, se tiene $A \subseteq B$, es decir, todos los elementos de $A$ cumplen $P$.

**Casos particulares.**

| Estructura          | Base                    | Paso                                                             |
| ------------------- | ----------------------- | ---------------------------------------------------------------- |
| Naturales           | $P(0)$                  | $P(n) \rightarrow P(S(n))$                                       |
| Listas              | $P([\,])$               | $P(\ell) \rightarrow P(x :: \ell)$ para todo $x$                 |
| Árboles binarios    | $P(\textsf{vacío})$     | $P(T_1) \land P(T_2) \rightarrow P(\textsf{nodo}(T_1, x, T_2))$ |
| Fórmulas            | $P(p)$ para cada variable | de $P(\varphi)$ a $P(\neg\varphi)$, y de $P(\varphi)$ y $P(\psi)$ a $P(\varphi \land \psi)$ y $P(\varphi \lor \psi)$ |

La inducción sobre los naturales es el caso de la primera fila: la inducción estructural la generaliza.

### 2. Dualidad entre recursión e inducción

Definir una función por recursión y demostrar una propiedad por inducción estructural son la misma operación vista desde dos lados:

| Recursión (calcular)                        | Inducción (demostrar)                            |
| ------------------------------------------- | ------------------------------------------------ |
| un caso de la función por cada constructor  | un caso de la demostración por cada constructor  |
| la llamada recursiva sobre una parte menor  | la hipótesis de inducción sobre esa parte        |
| el cálculo termina porque las partes se reducen | la demostración es válida por la cláusula de cierre |

Por eso, para demostrar algo sobre una función recursiva, la inducción se hace **sobre el mismo argumento sobre el que la función recursa**, y la demostración se escribe siguiendo sus ecuaciones.

### 3. Ejemplos con listas

Recuerde las definiciones del subtema 3.2:

$$
\begin{aligned}
\mathit{long}([\,]) &= 0 & \mathit{long}(x :: \ell) &= 1 + \mathit{long}(\ell) \\
[\,] \mathbin{+\!\!+} m &= m & (x :: \ell) \mathbin{+\!\!+} m &= x :: (\ell \mathbin{+\!\!+} m) \\
\mathit{rev}([\,]) &= [\,] & \mathit{rev}(x :: \ell) &= \mathit{rev}(\ell) \mathbin{+\!\!+} [x]
\end{aligned}
$$

**Proposición 1.** Para todas las listas $\ell$ y $m$, $\mathit{long}(\ell \mathbin{+\!\!+} m) = \mathit{long}(\ell) + \mathit{long}(m)$.

*Demostración* por inducción sobre $\ell$, porque $\mathbin{+\!\!+}$ recursa sobre su primer argumento. Sea $m$ cualquier lista.

- *Base,* $\ell = [\,]$: $\mathit{long}([\,] \mathbin{+\!\!+} m) = \mathit{long}(m) = 0 + \mathit{long}(m) = \mathit{long}([\,]) + \mathit{long}(m)$.
- *Paso,* $\ell = x :: \ell'$, con hipótesis $\mathit{long}(\ell' \mathbin{+\!\!+} m) = \mathit{long}(\ell') + \mathit{long}(m)$:

$$
\begin{aligned}
\mathit{long}((x :: \ell') \mathbin{+\!\!+} m) &= \mathit{long}(x :: (\ell' \mathbin{+\!\!+} m)) && \text{definición de } \mathbin{+\!\!+} \\
&= 1 + \mathit{long}(\ell' \mathbin{+\!\!+} m) && \text{definición de } \mathit{long} \\
&= 1 + \mathit{long}(\ell') + \mathit{long}(m) && \text{hipótesis de inducción} \\
&= \mathit{long}(x :: \ell') + \mathit{long}(m) && \text{definición de } \mathit{long} \qquad \square
\end{aligned}
$$

**Proposición 2.** Para toda lista $\ell$, $\mathit{rev}(\mathit{rev}(\ell)) = \ell$.

Un intento directo se atasca en el paso: hay que calcular $\mathit{rev}(\mathit{rev}(\ell') \mathbin{+\!\!+} [x])$, y la hipótesis no dice nada sobre la reversa de una concatenación. Es una situación frecuente: para demostrar el resultado hace falta antes un **lema** más general.

*Lemas auxiliares*, cada uno por inducción sobre $\ell$ con el mismo esquema que la proposición 1:

- (A) $\ell \mathbin{+\!\!+} [\,] = \ell$.
- (B) $(\ell \mathbin{+\!\!+} m) \mathbin{+\!\!+} k = \ell \mathbin{+\!\!+} (m \mathbin{+\!\!+} k)$.
- (C) $\mathit{rev}(\ell \mathbin{+\!\!+} m) = \mathit{rev}(m) \mathbin{+\!\!+} \mathit{rev}(\ell)$, que usa A en la base y B en el paso.

*Demostración de la proposición 2.* Base: $\mathit{rev}(\mathit{rev}([\,])) = \mathit{rev}([\,]) = [\,]$. Paso, con hipótesis $\mathit{rev}(\mathit{rev}(\ell')) = \ell'$:

$$
\begin{aligned}
\mathit{rev}(\mathit{rev}(x :: \ell')) &= \mathit{rev}(\mathit{rev}(\ell') \mathbin{+\!\!+} [x]) && \text{definición de } \mathit{rev} \\
&= \mathit{rev}([x]) \mathbin{+\!\!+} \mathit{rev}(\mathit{rev}(\ell')) && \text{lema C} \\
&= [x] \mathbin{+\!\!+} \ell' = x :: \ell' && \text{hipótesis y definiciones} \qquad \square
\end{aligned}
$$

### 4. Ejemplos con árboles

**Proposición 3.** En todo árbol binario $T$, el número de subárboles vacíos es $\mathit{tam}(T) + 1$.

Sea $v(T)$ el número de apariciones de $\textsf{vacío}$ en $T$, definido por $v(\textsf{vacío}) = 1$ y $v(\textsf{nodo}(T_1, x, T_2)) = v(T_1) + v(T_2)$.

- *Base:* $v(\textsf{vacío}) = 1 = 0 + 1 = \mathit{tam}(\textsf{vacío}) + 1$.
- *Paso:* con hipótesis $v(T_i) = \mathit{tam}(T_i) + 1$ para $i = 1, 2$:

$$v(\textsf{nodo}(T_1, x, T_2)) = (\mathit{tam}(T_1) + 1) + (\mathit{tam}(T_2) + 1) = \big(1 + \mathit{tam}(T_1) + \mathit{tam}(T_2)\big) + 1 = \mathit{tam}(\textsf{nodo}(T_1, x, T_2)) + 1 \qquad \square$$

En una implementación con apuntadores, esto dice que un árbol de $n$ nodos tiene exactamente $n + 1$ apuntadores nulos.

**Proposición 4.** Todo árbol binario de altura $h$ tiene a lo sumo $2^{h+1} - 1$ nodos.

- *Base:* $\textsf{vacío}$ tiene altura $-1$ y $0 = 2^0 - 1$ nodos.
- *Paso:* si $T = \textsf{nodo}(T_1, x, T_2)$ tiene altura $h$, cada $T_i$ tiene altura a lo sumo $h - 1$ y, por hipótesis, a lo sumo $2^h - 1$ nodos. Entonces $\mathit{tam}(T) \leq 1 + 2(2^h - 1) = 2^{h+1} - 1$. $\square$

Equivalentemente, un árbol con $n$ nodos tiene altura al menos $\log_2(n + 1) - 1$. Es la razón por la que las búsquedas en árboles balanceados cuestan del orden de $\log n$ pasos.

**Proposición 5 (árboles estrictos).** Los **árboles binarios estrictos** se definen así: una $\textsf{hoja}$ es un árbol estricto, y si $T_1$ y $T_2$ lo son, $\textsf{interno}(T_1, T_2)$ también. En todo árbol estricto, el número de hojas es igual al número de nodos internos más uno.

- *Base:* una hoja tiene 1 hoja y 0 nodos internos.
- *Paso:* si $T_i$ tiene $h_i$ hojas e $i_i = h_i - 1$ nodos internos, el árbol $\textsf{interno}(T_1, T_2)$ tiene $h_1 + h_2$ hojas y $i_1 + i_2 + 1 = (h_1 - 1) + (h_2 - 1) + 1 = h_1 + h_2 - 1$ nodos internos. $\square$

Observe que la definición del conjunto determina qué afirmación es verdadera: para los árboles binarios de la proposición 3, que admiten nodos con un solo hijo, la relación entre hojas e internos no es fija. Por ejemplo, una cadena de tres nodos tiene una hoja y dos nodos internos.

### 5. Ejemplos con fórmulas

**Proposición 6.** En toda fórmula construida con variables y los conectivos $\neg$, $\land$, $\lor$, con paréntesis completos según la sintaxis del subtema 2.1, el número de apariciones de variables es igual al número de conectivos binarios más uno.

Sean $a(\varphi)$ las apariciones de variables y $b(\varphi)$ las de conectivos binarios.

- *Base:* para una variable $p$, $a(p) = 1 = 0 + 1$.
- *Paso con* $\neg$: $a(\neg \varphi) = a(\varphi) = b(\varphi) + 1 = b(\neg \varphi) + 1$.
- *Paso con* $\land$ *o* $\lor$: $a(\varphi \land \psi) = a(\varphi) + a(\psi) = b(\varphi) + 1 + b(\psi) + 1 = b(\varphi \land \psi) + 1$, porque $b(\varphi \land \psi) = b(\varphi) + b(\psi) + 1$. $\square$

**Proposición 7.** Si una fórmula usa solo variables, $\land$ y $\lor$, entonces es verdadera en la interpretación que hace verdaderas a todas las variables.

La demostración es inmediata por inducción estructural: las variables son verdaderas, y la conjunción y la disyunción de fórmulas verdaderas son verdaderas. **Consecuencia:** la negación no puede expresarse usando solo $\land$ y $\lor$, porque $\neg p$ es falsa en esa interpretación. La inducción estructural sirve también para demostrar que algo es **imposible**.

### 6. Esquema de trabajo y errores frecuentes

**Esquema.**

1. Identificar el conjunto y su definición recursiva, y sobre qué argumento se hará la inducción: aquel sobre el que recursan las funciones involucradas.
2. Escribir la propiedad $P$ con precisión, indicando qué variables quedan fijas y cuáles se cuantifican.
3. Demostrar un caso por **cada** cláusula base y **cada** regla de construcción.
4. En cada paso, usar las definiciones de las funciones y la hipótesis de inducción, señalando dónde se usa.

**Errores frecuentes.**

- **Olvidar un constructor.** Si las fórmulas incluyen $\rightarrow$, la demostración debe tener ese caso aunque se parezca al de $\land$.
- **Usar la hipótesis sobre algo que no es una componente.** En el paso para $x :: \ell$ la hipótesis vale para $\ell$, no para listas arbitrarias.
- **Elegir mal el argumento de la inducción.** Para demostrar algo sobre $\ell \mathbin{+\!\!+} m$ conviene inducir sobre $\ell$, ya que inducir sobre $m$ obliga a razonar sobre ecuaciones que la definición no proporciona.
- **Afirmación demasiado débil.** Como en la proposición 2, a veces hay que demostrar un enunciado más general para que la hipótesis sea lo bastante fuerte.

### 7. Probar no es lo mismo que demostrar

Las pruebas automáticas basadas en propiedades generan cientos de datos aleatorios y verifican una propiedad en cada uno. Son muy útiles para encontrar errores, pero solo la demostración garantiza que la propiedad vale para **todas** las listas o árboles, que son infinitos.

```python
import random

def rev(l):
    return [] if not l else rev(l[1:]) + [l[0]]

for _ in range(1000):
    l = [random.randint(0, 9) for _ in range(random.randint(0, 20))]
    m = [random.randint(0, 9) for _ in range(random.randint(0, 20))]
    assert rev(rev(l)) == l
    assert rev(l + m) == rev(m) + rev(l)
print("Mil casos sin contraejemplos; la demostración está en la sección 3.")
```

> **Conexión con CC.** En los asistentes de demostración como Coq o Lean, declarar un tipo recursivo genera automáticamente su principio de inducción estructural, y las demostraciones de esta página se escriben casi línea por línea. En el diseño de compiladores, las propiedades de los árboles de sintaxis, como que una transformación preserve el significado de un programa, se demuestran por inducción estructural sobre el árbol.

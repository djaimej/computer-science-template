# Modelado y Programación - Programación concurrente

## 5.1 Introducción y contexto.

---

### 1. Definición y Conceptos Fundamentales

#### 1.1 ¿Qué es la Programación Concurrente?

La **programación concurrente** es un paradigma de programación que permite la ejecución de múltiples tareas aparentemente simultáneas dentro de un mismo programa. Estas tareas pueden ejecutarse en:

- **Procesadores múltiples** (paralelismo real)
- **Un solo procesador** mediante time-sharing (concurrencia)

**Concurrencia no es lo mismo que paralelismo.** La concurrencia trata de *estructurar* un programa como varias tareas que progresan de forma independiente y cuyos pasos pueden **intercalarse**; el paralelismo es *ejecutar* realmente varias instrucciones en el mismo instante, en varios núcleos. Un programa concurrente puede correr en un solo núcleo, alternando entre tareas, y aun así tener todos los problemas de sincronización de este capítulo.

Se usa concurrencia para:

- **Aprovechar varios núcleos** en cálculos largos.
- **No quedarse esperando**: mientras una tarea espera al disco o a la red, otra puede avanzar.
- **Responder a varios clientes o eventos** a la vez, como un servidor web o una interfaz gráfica.

#### 1.2 Términos Clave

- **Proceso**: Instancia de un programa en ejecución con su propio espacio de memoria
- **Hilo (Thread)**: Unidad básica de ejecución dentro de un proceso
- **Sección crítica**: Porción de código que accede a recursos compartidos
- **Race condition**: Condición donde el resultado depende del orden de ejecución
- **Deadlock**: Situación donde dos o más procesos se bloquean mutuamente
- **Inanición (*starvation*)**: un hilo nunca obtiene el recurso que necesita porque otros siempre se le adelantan

Los hilos de un mismo proceso **comparten** la memoria (variables globales, objetos en el *heap*), pero cada uno tiene su propia pila y su propio contador de programa. Por eso comunicarse entre hilos es barato, pero también es fácil que interfieran.

### 3. Conceptos Matemáticos Fundamentales

#### 3.1 Ley de Amdahl

Define la mejora máxima de velocidad mediante paralelización:

$$ S(n) = \frac{1}{(1 - p) + \frac{p}{n}} $$

Donde:

- $S(n):$ Speedup con n procesadores
- $p:$ Porción paralelizable del programa
- $n:$ Número de procesadores

Cuando $n \to \infty,$ $S(n) \to \frac{1}{1 - p}:$ la parte secuencial limita la mejora sin importar cuántos procesadores se agreguen. El tema 5.2 la estudia con detalle.

#### 3.2 Intercalaciones

Si dos hilos ejecutan $m$ y $n$ pasos atómicos, el número de órdenes posibles en que se pueden intercalar es

$$ \binom{m + n}{m} = \frac{(m + n)!}{m! \, n!} $$

Con solo 10 pasos por hilo hay $\binom{20}{10} = 184\,756$ intercalaciones. Por eso las pruebas casi nunca encuentran todos los errores de concurrencia: un error puede aparecer en una sola intercalación entre miles, y solo de vez en cuando. Hay que **razonar** sobre la corrección, no solo probar.

### 4. Ejemplos de Código

#### 4.1 Ejemplo Básico en Python (threading)

```python
import threading
import time

def tarea_imprimir(nombre, delay):
    """Función que simula una tarea concurrente"""
    for i in range(5):
        time.sleep(delay)
        print(f"{nombre}: Iteración {i}")

# Crear hilos
hilo1 = threading.Thread(target=tarea_imprimir, args=("Hilo-A", 0.5))
hilo2 = threading.Thread(target=tarea_imprimir, args=("Hilo-B", 0.3))

# Iniciar hilos
hilo1.start()
hilo2.start()

# Esperar a que terminen
hilo1.join()
hilo2.join()

print("Todos los hilos han terminado")
```

#### 4.2 Ejemplo en Java

```java
public class EjemploConcurrencia {
    public static void main(String[] args) {
        // Crear dos hilos
        Thread hilo1 = new Thread(new TareaRunnable("Hilo-1"));
        Thread hilo2 = new Thread(new TareaRunnable("Hilo-2"));

        // Iniciar hilos
        hilo1.start();
        hilo2.start();

        try {
            // Esperar a que terminen
            hilo1.join();
            hilo2.join();
        } catch (InterruptedException e) {
            e.printStackTrace();
        }

        System.out.println("Programa principal terminado");
    }
}

class TareaRunnable implements Runnable {
    private String nombre;

    public TareaRunnable(String nombre) {
        this.nombre = nombre;
    }

    @Override
    public void run() {
        for (int i = 0; i < 5; i++) {
            System.out.println(nombre + ": " + i);
            try {
                Thread.sleep(100); // Simular trabajo
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}
```

### 5. Problemas Comunes en Programación Concurrente

#### 5.1 Condición de Carrera (Race Condition)

```python
import threading

contador = 0

def incrementar():
    global contador
    for _ in range(100000):
        contador += 1  # Operación no atómica

# Crear hilos
hilo1 = threading.Thread(target=incrementar)
hilo2 = threading.Thread(target=incrementar)

hilo1.start()
hilo2.start()

hilo1.join()
hilo2.join()

print(f"Valor final del contador: {contador}")
# ¡El resultado puede ser menor que 200000!
```

`contador += 1` no es atómica: son tres pasos, **leer** el valor, **sumar** uno y **escribir** el resultado. Si el hilo 1 lee 41, el planificador lo suspende, el hilo 2 lee también 41 y escribe 42, y luego el hilo 1 escribe 42, se perdió un incremento.

En CPython el *Global Interpreter Lock* (GIL) solo deja ejecutar código Python a un hilo a la vez y cambia de hilo en puntos concretos, así que este ejemplo a veces da 200000 y a veces no, según la versión y la máquina. **El GIL no hace atómicas las operaciones compuestas**; la solución correcta es un candado (tema 5.3). En Java o C el error aparece casi siempre.

#### 5.2 Deadlock (Interbloqueo)

```python
import threading

recurso_a = threading.Lock()
recurso_b = threading.Lock()

def proceso1():
    with recurso_a:
        print("Proceso1 adquirió recurso A")
        with recurso_b:
            print("Proceso1 adquirió recurso B")

def proceso2():
    with recurso_b:
        print("Proceso2 adquirió recurso B")
        with recurso_a:  # ¡Peligro de deadlock!
            print("Proceso2 adquirió recurso A")
```

Si cada hilo alcanza a tomar su primer candado antes de que el otro tome el segundo, ambos esperan para siempre. Un interbloqueo solo es posible si se cumplen a la vez las cuatro **condiciones de Coffman**: exclusión mutua, retener y esperar, no apropiación, y espera circular. Basta romper una; la forma más común es imponer un **orden global** a los recursos: si todos los hilos toman siempre `recurso_a` antes que `recurso_b`, la espera circular es imposible.

#### Ejercicio 2: Detección de Problemas

Identifica los problemas en el siguiente código:

```python
import threading

total = 0

def sumar():
    global total
    for i in range(1000):
        total += i

def restar():
    global total
    for i in range(1000):
        total -= i

hilos = []
for _ in range(10):
    hilos.append(threading.Thread(target=sumar))
    hilos.append(threading.Thread(target=restar))

for hilo in hilos:
    hilo.start()

for hilo in hilos:
    hilo.join()

print(f"Total final: {total}")
```

#### Ejercicio 3: Diseño de Sistema Concurrente

Diseña un sistema concurrente para procesar 1000 imágenes donde cada imagen necesita:

- 0.1s para cargar
- 0.5s para procesar
- 0.2s para guardar

Calcula el tiempo teórico con 1, 4 y 8 hilos.

### 7. Soluciones a Ejercicios

#### Solución Ejercicio 1:

a) $S(4) = \frac{1}{(1 - 0.7) + \frac{0.7}{4}} = \frac{1}{0.3 + 0.175} = \frac{1}{0.475} ≈ 2.10$

b) $S(8) = \frac{1}{0.3 + \frac{0.7}{8}} = \frac{1}{0.3 + 0.0875} = \frac{1}{0.3875} ≈ 2.58$

c) $S(16) = \frac{1}{0.3 + \frac{0.7}{16}} = \frac{1}{0.3 + 0.04375} = \frac{1}{0.34375} ≈ 2.91$

#### Solución Ejercicio 2:

El código tiene una **condición de carrera** porque múltiples hilos acceden y modifican la variable `total` sin sincronización. El resultado correcto es 0, pues 10 hilos suman $0 + 1 + \cdots + 999 = 499\,500$ y otros 10 restan lo mismo, pero se pueden perder actualizaciones y obtener cualquier otro valor. Se corrige protegiendo `total += i` y `total -= i` con un mismo `threading.Lock`, o haciendo que cada hilo acumule en una variable local y sume su resultado una sola vez, dentro del candado.

#### Solución Ejercicio 3:

**Tiempo secuencial**: $1000 × (0.1 + 0.5 + 0.2) = 800s$

**Con n hilos**: $T(n) = \frac{800}{n} + T_{overhead}$

Como cada imagen es independiente, el problema es **vergonzosamente paralelo**: idealmente $T(1) = 800$ s, $T(4) = 200$ s y $T(8) = 100$ s, siempre que haya al menos 8 núcleos. En la práctica la carga y el guardado compiten por el disco, y en Python el procesamiento con hilos no se acelera por el GIL; para cálculo intensivo se usan procesos (`multiprocessing`) o bibliotecas que liberan el GIL.

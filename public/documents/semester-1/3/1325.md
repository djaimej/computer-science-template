## 2.5 Uso de bibliotecas.

---

Ningún programa se escribe desde cero. Ordenar una lista, calcular una raíz cuadrada, manejar fechas o leer un archivo son tareas resueltas, probadas y optimizadas en **bibliotecas**: colecciones de clases listas para usarse. Saber encontrarlas, leer su documentación y usarlas correctamente es una habilidad tan importante como saber programar, y la orientación a objetos la facilita: una biblioteca se usa creando sus objetos y enviándoles mensajes, sin conocer su implementación.

### 1. Biblioteca, API y marco de trabajo

- Una **biblioteca** es un conjunto de clases y métodos reutilizables. El programa decide cuándo llamarlos.
- La **API** (interfaz de programación de aplicaciones) de una biblioteca es la parte pública que puede usarse: clases, métodos, sus parámetros y lo que garantizan. Es un contrato: mientras la API no cambie, la implementación puede mejorar sin afectar a quien la usa.
- Un **marco de trabajo** (framework) invierte el control: el marco dirige la ejecución y llama al código del programador en momentos determinados. Spring en Java o Angular en TypeScript son marcos de trabajo.

### 2. La biblioteca estándar de Java

Todo JDK incluye miles de clases organizadas en paquetes. Algunas de las más usadas:

| Paquete           | Contenido                                        | Clases representativas                              |
| ----------------- | ------------------------------------------------ | --------------------------------------------------- |
| `java.lang`       | lo esencial, se importa automáticamente          | `String`, `Math`, `Integer`, `System`, `Object`     |
| `java.util`       | colecciones y utilidades                         | `ArrayList`, `HashMap`, `Arrays`, `Collections`, `Random`, `Scanner` |
| `java.time`       | fechas, horas y duraciones                       | `LocalDate`, `LocalDateTime`, `Duration`            |
| `java.nio.file`   | archivos y directorios                           | `Files`, `Path`                                     |
| `java.math`       | números de precisión arbitraria                  | `BigInteger`, `BigDecimal`                          |
| `java.util.stream`| procesamiento funcional de colecciones           | `Stream`, `IntStream`                               |
| `java.net.http`   | peticiones HTTP                                  | `HttpClient`                                        |

### 3. Cómo se usa una clase de biblioteca

Hay dos formas básicas, según la clase ofrezca métodos de instancia o métodos estáticos:

```java
import java.math.BigInteger;
import java.time.DayOfWeek;
import java.time.LocalDate;
import java.time.temporal.ChronoUnit;
import java.util.ArrayList;
import java.util.Collections;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.Random;

public class TourBiblioteca {
    public static void main(String[] args) {
        // Métodos estáticos: se invocan sobre la clase
        System.out.println(Math.sqrt(2));                 // 1.4142135623730951
        System.out.println(Math.max(3, 7));               // 7
        System.out.println(Integer.parseInt("42") + 1);   // 43

        // Objetos: se crean con new o con un método de fábrica, y se les envían mensajes
        List<String> nombres = new ArrayList<>(List.of("Luis", "Ana", "Eva"));
        Collections.sort(nombres);
        System.out.println(nombres);                      // [Ana, Eva, Luis]

        Map<String, Integer> edades = new HashMap<>();
        edades.put("Ana", 20);
        edades.put("Luis", 22);
        System.out.println(edades.get("Ana"));            // 20
        System.out.println(edades.getOrDefault("Eva", 0)); // 0

        LocalDate hoy = LocalDate.of(2025, 1, 15);
        LocalDate entrega = hoy.plusWeeks(3);
        System.out.println(entrega + " cae en " + entrega.getDayOfWeek());   // 2025-02-05 cae en WEDNESDAY
        System.out.println(ChronoUnit.DAYS.between(hoy, entrega) + " días"); // 21 días
        System.out.println(entrega.getDayOfWeek() == DayOfWeek.WEDNESDAY);   // true

        BigInteger factorial = BigInteger.ONE;
        for (int i = 2; i <= 30; i++) factorial = factorial.multiply(BigInteger.valueOf(i));
        System.out.println(factorial);                    // 30!, que no cabe en un long

        Random azar = new Random(2025);                   // con semilla: resultados reproducibles
        System.out.println(azar.nextInt(6) + 1);          // un dado
    }
}
```

Los tipos entre picoparéntesis, como `List<String>` o `Map<String, Integer>`, son **genéricos**: indican qué tipo de elementos guarda la colección, y el compilador verifica que no se mezclen.

### 4. Leer la documentación

La documentación de la API de Java se genera con Javadoc y está en línea. Para cada método indica:

- su **firma**: nombre, parámetros y tipo de regreso;
- una **descripción** de lo que hace;
- sus **precondiciones**, es decir, qué valores de los parámetros son válidos;
- las **excepciones** que puede lanzar y en qué casos;
- la versión de Java desde la que existe.

**Ejemplo.** La documentación de `String.substring(int beginIndex, int endIndex)` dice que regresa los caracteres desde `beginIndex` **inclusive** hasta `endIndex` **exclusive**, y que lanza `IndexOutOfBoundsException` si los índices son negativos, si `endIndex` excede la longitud o si `beginIndex > endIndex`. Así, `"computadora".substring(0, 4)` es `"comp"`. Leer esa información antes de usar un método evita la mayoría de los errores.

Un hábito útil al encontrar un método nuevo es probarlo en **JShell**, la consola interactiva de Java que viene con el JDK:

```text
$ jshell
jshell> "computadora".substring(0, 4)
$1 ==> "comp"
jshell> java.time.LocalDate.of(2024, 2, 29).plusYears(1)
$2 ==> 2025-02-28
```

### 5. Bibliotecas externas

Para lo que no está en la biblioteca estándar existen miles de bibliotecas de terceros, publicadas en repositorios como **Maven Central**. Una herramienta de construcción las descarga a partir de una declaración en el proyecto:

```xml
<!-- pom.xml de Maven -->
<dependency>
    <groupId>com.google.code.gson</groupId>
    <artifactId>gson</artifactId>
    <version>2.11.0</version>
</dependency>
```

```java
import com.google.gson.Gson;

record Alumno(String nombre, double promedio) {}

// en algún método:
Gson gson = new Gson();
String json = gson.toJson(new Alumno("Ana", 9.5));        // {"nombre":"Ana","promedio":9.5}
Alumno a = gson.fromJson(json, Alumno.class);
```

**Versiones.** Muchas bibliotecas siguen el **versionado semántico** `MAYOR.MENOR.PARCHE`: un cambio en el número de parche corrige errores, uno menor agrega funciones sin romper compatibilidad y uno mayor puede romperla. Fijar las versiones evita que el proyecto cambie de comportamiento sin aviso.

**Dependencias transitivas.** Una biblioteca puede depender de otras, que dependen de otras más. Cuando dos bibliotecas exigen versiones incompatibles de una tercera surge el llamado "infierno de dependencias", que las herramientas de construcción ayudan a resolver.

### 6. Criterios para elegir una biblioteca

- **¿Ya existe en la biblioteca estándar?** Si es así, suele ser la mejor opción.
- **Mantenimiento:** ¿se actualiza con regularidad?, ¿responde a reportes de errores?
- **Documentación y comunidad:** ¿hay ejemplos y respuestas a preguntas frecuentes?
- **Licencia:** las licencias permisivas, como MIT y Apache, permiten casi cualquier uso; las de tipo copyleft, como GPL, obligan a publicar bajo la misma licencia el software que las incorpora.
- **Seguridad:** las vulnerabilidades en dependencias son una de las principales vías de ataque. En 2021, una falla en la biblioteca de registro Log4j afectó a una enorme cantidad de sistemas en todo el mundo.
- **Tamaño:** agregar una biblioteca grande para usar una sola función aumenta la complejidad del proyecto.

> **Conexión con CC.** Las estructuras de datos de `java.util`, como `ArrayList`, `LinkedList` y `HashMap`, se implementan desde cero en Estructuras de Datos (Sem. 2). Entender cómo funcionan por dentro permite elegir la adecuada: buscar un elemento en un `ArrayList` revisa uno por uno, mientras que en un `HashMap` la búsqueda toma en promedio tiempo constante. La biblioteca es una herramienta, no un sustituto de entender los algoritmos.

### Ejercicios propuestos

1. Use `Arrays.sort` y `Arrays.binarySearch` para ordenar un arreglo de enteros y buscar un valor. Consulte en la documentación qué regresa `binarySearch` cuando el valor no está.
2. Escriba un programa que pida una fecha de nacimiento y calcule la edad exacta en años, meses y días usando `java.time.Period`.
3. Use un `HashMap<String, Integer>` para contar cuántas veces aparece cada palabra en un texto.
4. Calcule $2^{200}$ y el factorial de 100 con `BigInteger`, y verifique cuántos dígitos tiene cada resultado.
5. Busque en la documentación la diferencia entre `String.equals` y `==`, y entre `String.equals` y `String.equalsIgnoreCase`. Escriba un ejemplo de cada caso.
6. Investigue la licencia de dos bibliotecas de Java populares y explique qué permite y qué exige cada una.
